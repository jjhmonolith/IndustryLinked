## 0. 이 차시 한눈에
- **목표**: 1일차 챗봇 MVP를 트랙 주제에 맞는 '진짜 수업 도구'로, 짓다에서 AI와 대화하며 발전시킨다.
- **산출물**: 트랙 A — 자동 채점 + 수준별 힌트 + 코드 해설이 한 흐름으로 도는 튜터 v1 / 트랙 B — 내 수업자료로 만든 지식 베이스 + 자료 범위 안에서만 답하는 챗봇 v1.
- **앞 차시 연결**: 1일차에 만든 챗봇 MVP·아이디어, 업스테이지·Colab에서 다룬 Document Parse 실습 결과(구조화·핵심추출 자료).
- **다음 차시 연결**: 2차시(11:00–12:00) '도구 안전성 점검'에서 오늘 만든 도구에 안전장치를 붙인다.

> **오늘의 제작 도구는 '짓다'**: 팀모노리스의 바이브코딩 플랫폼. 코드를 직접 쓰지 않고, 왼쪽 **AI 채팅**에 한국어로 "이런 도구 만들어줘"라고 말하면 AI가 만들고, 오른쪽 **라이브 미리보기**에서 바로 확인한다. 바꾸고 싶으면 다시 말한다. 완성작은 **갤러리**에 공개·호스팅된다. AI 모델은 **Solar** 연동. 설치·로그인·명령어 없이 브라우저만.

### 트랙 A — 핵심 개념·실습 지시

#### [핵심 개념 · 채점] (09:20–09:35)
[강사 멘트] "자동 채점의 핵심은 단순합니다. 학생 코드를 실행한 결과를 정답이랑 비교하는 거예요. 통과면 넘어가고, 틀리면 '어디가 왜 틀렸는지'를 다음 단계인 힌트로 넘깁니다. 이걸 우리가 코딩하는 게 아니라, 짓다 AI 채팅에 '이렇게 만들어줘'라고 말로 요청합니다."

(talking point) 무한 루프·오류로 채점이 멈추는 문제도 요청 문장에 "잘못된 코드나 오래 걸리는 코드도 안전하게 처리해줘"를 함께 넣으면 짓다가 알아서 처리한다고 안내.

**[화면 · 짓다 AI 채팅에 이렇게 요청]**
```text
파이썬 문제 하나를 풀게 하고, 학생이 제출한 코드를
미리 정한 테스트케이스로 자동 채점하는 웹앱을 만들어줘.
- 통과/실패를 정확히 갈라서 보여주고
- 틀린 케이스는 (입력, 기대값, 실제출력)을 표로 보여줘
- 잘못된 코드나 오래 걸리는 코드도 앱이 멈추지 않게 안전하게 처리해줘
```

[실습] (09:35–09:55)
1. 짓다에서 새 프로젝트를 만든다(도구 이름·목적 입력).
2. AI 채팅에 위 요청을 넣고, 어제 준비한 예제 문제의 테스트케이스를 `(입력, 기대출력)` 형태로 3개 이상 넣어달라고 이어서 요청한다.
3. 라이브 미리보기에서 일부러 틀린 학생 코드 한 개를 넣어 실행해 본다.
4. 통과/실패와 실패 케이스가 제대로 나오는지 미리보기에서 확인한다. 어긋나면 "이렇게 바꿔줘"로 다시 요청한다.

[체크] 09:55–10:00 — 실패 케이스가 `(입력, 기대, 실제출력)`으로 표시되면 힌트 단계로 진행.

#### [핵심 개념 · 힌트] (10:00–10:10)
[강사 멘트] "이제 틀린 학생한테 힌트를 줄 차례인데, 여기가 이 연수의 핵심 철학이에요. 정답 코드를 통째로 주면 안 됩니다. 학생이 스스로 고치도록, '어느 줄의 무엇이 왜 문제인지' 한 문장으로 짚고 다음 시도를 위한 질문을 하나 던지게 만듭니다. 이 규칙을 짓다에 요청할 때 못 박아 둘 거예요."

**[화면 · 짓다 AI 채팅에 이어서 요청]**
```text
채점에서 틀리면, 정답 대신 힌트를 주도록 바꿔줘. 규칙은 이렇게 지켜줘.
- 정답 코드는 절대 보여주지 마
- "어느 줄의 무엇이 왜 문제인지"를 한 문장으로만 짚어줘
- 다음 시도를 위한 질문 하나를 던져줘
- 힌트 문구는 Solar로 생성해줘
```

[실습] (10:10–10:30)
1. 위 요청을 AI 채팅에 넣어 채점 도구에 힌트 기능을 붙인다.
2. 미리보기에서 틀린 코드를 넣어 힌트가 뜨는지 확인한다.
3. 생성된 힌트에 **정답 코드가 들어있지 않은지** 직접 눈으로 확인한다.
4. 정답 코드가 새어 나오면 "정답 코드는 절대 노출하지 마"를 더 강하게 붙여 다시 요청한다.

#### [핵심 개념 · 코드 해설 튜터] (10:30–10:40)
[강사 멘트] "마지막은 해설이에요. 힌트가 '스스로 고치게 하는 질문'이라면, 해설은 학생 수준의 자연어로 '네 코드에서 틀린 부분과 그 이유'를 짚어 주는 거예요. 채점 → 힌트 → 해설, 이 세 개가 하나의 흐름으로 이어지면 오늘 트랙 A 도구 v1이 완성됩니다."

[실습] (10:40–10:55)
1. AI 채팅에 "해설도 정답 코드는 그대로 주지 말고, 틀린 부분과 이유를 학생 눈높이 자연어로 설명해줘. Solar로."라고 요청한다.
2. 미리보기에서 같은 학생 코드로 해설을 띄워 틀린 줄·이유가 학생 눈높이로 설명되는지 확인한다.
3. "채점 → (틀리면) 힌트 → 해설이 한 흐름으로 이어지게 해줘"라고 요청해 세 기능을 하나로 잇는다.
4. 통과하는 코드와 틀리는 코드를 각각 미리보기에 넣어 흐름 전체를 한 번씩 돌린다.

## 4. 강의 가이드라인 (이 차시 특화)
- **강조점**: 기능의 개수가 아니라 '한 흐름이 끝까지 도는 도구 하나'. 트랙 A는 '정답을 대신 주지 않는다', 트랙 B는 '자료 밖은 정직하게 거절한다'가 각 트랙의 핵심 철학. 코드가 아니라 '무엇을·어떤 규칙으로'를 정하는 게 오늘의 일.
- **피해야 할 것**: 코드를 설명·받아쓰게 하는 강의(오늘은 짓다에 말로 요청). 규칙(정답 유출 금지 / 자료 밖 거절)을 요청에서 빠뜨리는 것. 미리보기로 확인 안 하고 넘어가는 것.
- **톤**: 비전공·저경험 교사 배려. 용어는 처음 나올 때 1줄로 풀고 화면은 크게·천천히. "코딩 못 해도 됩니다"를 반복.
- **시간 관리**: 실습 시간(트랙 A 채점·힌트 요청, 트랙 B 챗봇 제작·테스트)은 사수. 지연 시 부가 설명부터 줄인다. 트랙 B는 2개 반이 동시에 도니 반별 진도 편차를 코들 대시보드로 상시 확인.
