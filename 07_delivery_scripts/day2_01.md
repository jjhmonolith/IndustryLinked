### 트랙 A — 핵심 개념·실습 지시

#### [핵심 개념 · 채점] (09:20–09:35)
[강사 멘트] "자동 채점의 핵심은 단순합니다. 학생 코드를 실행한 결과를 정답이랑 비교하는 거예요. 통과면 넘어가고, 틀리면 '어디가 왜 틀렸는지'를 다음 단계인 힌트로 넘깁니다. 채점기 자체가 똑똑할 필요는 없어요. 통과/실패만 정확히 갈라주면 됩니다."

(talking point) 무한 루프·오류로 채점이 멈추지 않게 샌드박스 실행 함수는 타임아웃·예외처리가 들어간 템플릿을 그대로 쓰라고 강조.

```python
def grade_submission(student_code: str, testcases: list[tuple]) -> dict:
    """정답 비교 기반 자동 채점. 통과/실패와 실패 케이스를 반환."""
    passed, failed = [], []
    for inp, expected in testcases:
        got = run_student_code(student_code, inp)   # 타임아웃·예외처리 포함 샌드박스
        (passed if got == expected else failed).append((inp, expected, got))
    return {"score": len(passed) / len(testcases), "failed": failed}
```

[실습] (09:35–09:55)
1. 배포된 노트북에서 `grade_submission`과 `run_student_code` 템플릿을 찾는다.
2. 어제 준비한 예제 문제의 테스트케이스를 `(입력, 기대출력)` 형태로 3개 이상 넣는다.
3. 일부러 틀린 학생 코드 한 개를 넣어 실행한다.
4. 반환값에 `score`와 `failed`(실패 케이스)가 제대로 나오는지 확인한다.

[체크] 09:55–10:00 — 실패 케이스가 `(입력, 기대, 실제출력)`으로 반환되면 힌트 단계로 진행.

#### [핵심 개념 · 힌트] (10:00–10:10)
[강사 멘트] "이제 틀린 학생한테 힌트를 줄 차례인데, 여기가 이 연수의 핵심 철학이에요. 정답 코드를 통째로 주면 안 됩니다. 학생이 스스로 고치도록, '어느 줄의 무엇이 왜 문제인지' 한 문장으로 짚고 다음 시도를 위한 질문을 하나 던지게 만듭니다. 이 규칙을 프롬프트에 못 박아 둘 거예요."

```python
# 실패 시 → 학생 수준 힌트 생성 (Solar LLM API)
HINT_PROMPT = """너는 중학생에게 파이썬을 가르치는 친절한 튜터다.
아래 학생 코드는 입력 {inp}에서 {expected} 대신 {got}을 출력했다.
[규칙] 정답 코드를 그대로 주지 마라. 학생이 스스로 고치도록
'어느 줄의 무엇이 왜 문제인지'를 한 문장으로 짚고, 다음 시도를 위한 질문 하나를 던져라.
학생 코드:
{student_code}"""
```

[실습] (10:10–10:30)
1. 채점 결과의 `failed`에서 실패 케이스 하나를 꺼낸다.
2. `HINT_PROMPT`에 `inp`·`expected`·`got`·`student_code`를 채워 Solar API로 힌트를 생성한다.
3. 생성된 힌트에 **정답 코드가 들어있지 않은지** 직접 눈으로 확인한다.
4. 정답 코드가 새어 나오면 규칙 문구를 더 강하게 다듬어 다시 호출한다.

#### [핵심 개념 · 코드 해설 튜터] (10:30–10:40)
[강사 멘트] "마지막은 해설이에요. 힌트가 '스스로 고치게 하는 질문'이라면, 해설은 학생 수준의 자연어로 '네 코드에서 틀린 부분과 그 이유'를 짚어 주는 거예요. 채점 → 힌트 → 해설, 이 세 개가 하나의 흐름으로 이어지면 오늘 트랙 A 도구 v1이 완성됩니다."

[실습] (10:40–10:55)
1. 해설 프롬프트에도 '정답 코드를 그대로 주지 않는다' 규칙을 넣는다.
2. 같은 학생 코드로 해설을 생성해 틀린 줄·이유가 학생 눈높이로 설명되는지 확인한다.
3. `채점 → (실패 시) 힌트 → 해설`을 한 셀에서 순서대로 호출되게 연결한다.
4. 통과하는 코드와 틀리는 코드를 각각 넣어 흐름 전체를 한 번씩 돌린다.

### 트랙 B — 핵심 개념·실습 지시

#### [핵심 개념 · 지식 베이스 구축] (09:20–09:35)
[강사 멘트] "트랙 B의 도구는 '내 수업자료 안에서만 답하는 챗봇'이에요. 그러려면 먼저 자료를 챗봇이 읽을 수 있는 형태로 바꿔야 합니다. 순서는 이래요. 문서를 Document Parse로 구조화하고, Information Extract로 핵심 항목만 뽑아서 지식 베이스를 만들고, 챗봇은 그 지식 베이스 안에서만 답합니다."

(talking point) 표·수식이 많은 자료는 Document Parse가 잘 못 잡을 수 있으니 텍스트가 깔끔한 단원부터 시작. 파싱 결과는 반드시 육안 검수.

[실습] (09:35–10:00)
1. 본인 수업자료 PDF/텍스트(1개 단원)를 Document Parse에 업로드한다.
2. 파싱 결과로 나온 구조(제목·소단원·문단)를 화면에서 눈으로 검수한다.
3. 표·그림이 깨졌으면 그 부분은 제외하거나 텍스트가 깔끔한 단원으로 교체한다.

#### [핵심 개념 · 핵심 추출·응답] (10:00–10:10, 10:40–10:45)
[강사 멘트] "Information Extract로는 이 단원에서 학생이 알아야 할 핵심 항목만 정리합니다. 이게 챗봇의 지식 베이스가 돼요. 그리고 가장 중요한 규칙 하나. 챗봇은 이 자료 안에 있는 내용만 답하고, 자료에 없으면 지어내지 말고 정직하게 거절합니다. 챗봇의 신뢰는 '모른다고 말하는 정직함'에서 나와요."

```text
[시스템 프롬프트 — 자료 기반 응답 · 거절]
너는 아래 <학습자료>에만 근거해 답하는 학습 보조 챗봇이다.

규칙:
1) 답변은 반드시 <학습자료> 안의 내용으로만 구성한다.
2) 근거가 자료에 없으면 지어내지 말고 이렇게 거절한다:
   "그 내용은 이번 수업자료 범위에 없어요. 자료에 있는 OO, OO에 대해서는 도와줄 수 있어요."
3) 답변 끝에 근거가 된 자료의 항목(제목/소단원)을 표시한다.

<학습자료>
{information_extract_결과_핵심항목들}
</학습자료>

학생 질문: {question}
```

[실습 · 추출] (10:10–10:40)
1. 파싱된 자료에서 Information Extract로 핵심 학습 항목(개념·정의·예시)을 뽑는다.
2. 뽑힌 항목이 이 단원의 학습 목표와 맞는지 확인하고 불필요한 항목은 정리한다.
3. 오늘은 범위를 넓히지 말고 **1개 단원**으로 지식 베이스를 완성한다.

[실습 · 응답] (10:45–10:55)
1. 위 시스템 프롬프트의 `{information_extract_결과_핵심항목들}`에 지식 베이스를 넣는다.
2. **자료 안에 있는 질문**을 하나 넣어 답변 끝에 근거 항목이 표시되는지 확인한다.
3. **자료 밖 질문**을 하나 넣어 지어내지 않고 거절 메시지가 나오는지 확인한다.
4. 거절이 안 되고 지어내면 규칙 1)·2)를 더 강하게 다듬어 다시 호출한다.

## 4. 강의 가이드라인 (이 차시 특화)
- **강조점**: 기능의 개수가 아니라 '한 흐름이 끝까지 도는 도구 하나'. 트랙 A는 '정답을 대신 주지 않는다', 트랙 B는 '자료 밖은 정직하게 거절한다'가 각 트랙의 핵심 철학.
- **피해야 할 것**: 코드 한 줄씩 받아쓰게 하는 강의(설명은 개념까지, 손은 학습자가). 검증 안 된 기능 라이브 시연.
- **톤**: 비전공·저경험 교사 배려. 용어는 처음 나올 때 1줄로 풀고 화면은 크게·천천히.
- **시간 관리**: 실습 시간(트랙 A 채점·힌트, 트랙 B 업로드·추출)은 사수. 지연 시 부가 설명부터 줄인다. 트랙 B는 2개 반이 동시에 도니 반별 진도 편차를 코들 대시보드로 상시 확인.
