## 0. 이 차시 한눈에
- **목표**: 1일차에 스케치한 아이디어를 트랙 주제에 맞는 '진짜 수업 도구'로, 짓다에서 AI와 대화하며 발전시킨다.
- **산출물**: 트랙 A — 학생 코드를 자동 채점하고 틀리면 정답 대신 힌트를 주는 튜터 v1 / 트랙 B — 정한 주제로 학생과 대화하며 답 대신 질문을 던지고, 대화를 다섯 관점으로 평가해 등급을 매기는 대화 튜터 v1.
- **앞 차시 연결**: 1일차에 시연으로 본 두 도구(코들의 파이썬 자동 채점·AI 튜터 / 소크룸 대화 튜터)와 각자 정한 수업 문제·첫 스케치.
- **다음 차시 연결**: 2차시(11:00–12:00) '도구 안전성 점검'에서 오늘 만든 도구에 안전장치를 붙인다.

> **오늘의 제작 도구는 '짓다'**: 팀모노리스의 바이브코딩 플랫폼. 코드를 직접 쓰지 않고, 왼쪽 **AI 채팅**에 한국어로 "이런 도구 만들어줘"라고 말하면 AI가 만들고, 오른쪽 **라이브 미리보기**에서 바로 확인한다. 바꾸고 싶으면 다시 말한다. 완성작은 **갤러리**에 공개·호스팅된다. AI 모델은 **Solar** 연동. 설치·로그인·명령어 없이 브라우저만.

### 트랙 A — 핵심 개념·실습 지시

#### [핵심 개념 · 채점] (09:20–09:35)
[강사 멘트] "자동 채점의 핵심은 단순합니다. 학생이 낸 코드를, 제가 미리 등록해 둔 정답·예시와 비교해서 맞았는지 틀렸는지 자동으로 가려 주는 거예요. 맞으면 넘어가고, 틀리면 다음 단계인 '힌트'로 넘깁니다. 문제랑 정답 예시는 직접 넣어도 되고, AI한테 만들어 달라고 해도 됩니다. 이걸 우리가 코딩하는 게 아니라, 짓다 AI 채팅에 '이렇게 만들어줘'라고 말로 요청합니다."

(talking point) 학생이 이상한 코드를 내서 앱이 멈추는 문제도, 요청 문장에 "잘못되거나 오래 걸리는 코드가 들어와도 앱이 멈추지 않게 해줘"를 함께 넣으면 짓다가 알아서 처리한다고 안내.

**[화면 · 짓다 AI 채팅에 이렇게 요청]**
```text
학생이 낸 파이썬 코드를 자동으로 채점하는 웹앱을 만들어줘.
- 내가 등록한 정답·예시와 비교해서 맞음/틀림을 정확히 가려 줘
- 어떤 입력에 어떤 답이 나와야 하는지 몇 개 넣을 테니 그걸로 채점해줘
- 잘못되거나 너무 오래 걸리는 코드가 들어와도 앱이 멈추지 않게 해줘
```

[실습] (09:35–09:55)
1. 짓다에서 새 프로젝트를 만든다(도구 이름·목적 입력).
2. AI 채팅에 위 요청을 넣고, 어제 준비한 예제 문제로 "이 입력에는 이 답" 같은 예시를 3개 이상 넣어 채점 기준으로 삼아달라고 이어서 요청한다.
3. 라이브 미리보기에서 일부러 틀린 학생 코드 한 개를 넣어 실행해 본다.
4. 맞음/틀림이 제대로 갈리는지 미리보기에서 확인한다. 어긋나면 "이렇게 바꿔줘"로 다시 요청한다.

[체크] 09:55–10:00 — 틀린 코드에 '틀림'이 뜨면 힌트 단계로 진행.

#### [핵심 개념 · 힌트] (10:00–10:10)
[강사 멘트] "이제 틀린 학생한테 힌트를 줄 차례인데, 여기가 이 연수의 핵심 철학이에요. 정답을 그대로 알려주면 안 됩니다. 학생이 스스로 고치도록, '어디가 왜 막혔는지'만 짚어 주는 거예요. 이 규칙을 짓다에 요청할 때 못 박아 둘 거예요."

**[화면 · 짓다 AI 채팅에 이어서 요청]**
```text
채점에서 틀리면, 정답을 그대로 알려주지 말고 힌트만 주도록 바꿔줘. 규칙:
- 정답이나 정답 코드는 절대 보여주지 마
- "어디가 왜 막혔는지"를 한 문장으로만 짚어줘
- 힌트 문구는 Solar로 만들어줘
```

[실습] (10:10–10:30)
1. 위 요청을 AI 채팅에 넣어 채점 도구에 힌트 기능을 붙인다.
2. 미리보기에서 틀린 코드를 넣어 힌트가 뜨는지 확인한다.
3. 생성된 힌트에 **정답이 그대로 들어있지 않은지** 직접 눈으로 확인한다.
4. 정답이 새어 나오면 "정답은 절대 알려주지 마"를 더 강하게 붙여 다시 요청한다.

#### [핵심 개념 · 해결 방법 더 보기] (10:30–10:40)
[강사 멘트] "마지막으로, 힌트만 봐도 정 답답한 학생을 위해 '해결 방법' 버튼을 하나 답니다. 힌트가 '스스로 생각하게 하는 한 마디'라면, 해결 방법은 학생이 원할 때만 눌러서 조금 더 자세한 안내를 받는 거예요. 그래도 정답을 통째로 주진 않고요. 채점 → 힌트 → (원하면) 해결 방법, 이렇게 이어지면 오늘 트랙 A 도구 v1이 완성됩니다."

[실습] (10:40–10:55)
1. AI 채팅에 "학생이 '해결 방법'을 누르면 조금 더 자세히 안내해줘. 그래도 정답은 그대로 주지 말고, 어떻게 접근하면 좋을지 학생 눈높이로 설명해줘. Solar로."라고 요청한다.
2. 미리보기에서 같은 학생 코드로 '해결 방법'을 눌러 안내가 학생 눈높이로 나오는지 확인한다.
3. "채점 → (틀리면) 힌트 → (원하면) 해결 방법이 한 흐름으로 이어지게 해줘"라고 요청해 세 기능을 하나로 잇는다.
4. 맞는 코드와 틀리는 코드를 각각 미리보기에 넣어 흐름 전체를 한 번씩 돌린다.

### 트랙 B — 핵심 개념·실습 지시

#### [핵심 개념 · 주제와 유도 질문] (09:20–09:35)
[강사 멘트] "트랙 B의 도구는 정답을 채점하는 게 아니라, 정한 주제로 학생과 '대화'하면서 스스로 생각하게 이끄는 튜터예요. 먼저 제가 대화 주제와 난이도를 정합니다. 오늘은 '광합성'. 주제는 직접 써도 되고, PDF나 링크를 넣으면 AI가 정리해 줍니다. 그다음이 핵심인데 — 이 튜터는 답을 바로 알려주지 않고 질문을 던져요. '왜 그렇게 생각해요?', '근거는요?', '다른 관점도 있을까요?' 한 번에 하나씩요. 학생은 이 질문에 답하면서 자기 생각을 정리하게 됩니다. 이걸 짓다에 말로 요청합니다."

(talking point) 주제가 너무 넓으면 대화가 산만해지니, 오늘은 한 단원·한 주제로 좁히도록 안내. 만들다 보면 AI가 답을 바로 줘 버리는 경우가 있는데, 그때는 "답을 바로 주지 말고 반드시 질문으로 되묻게 해"를 더 강하게 붙여 다시 요청.

**[화면 · 짓다 AI 채팅에 이렇게 요청]**
```text
'광합성'을 주제로 학생과 대화하는 학습 튜터 웹앱을 만들어줘. 모델은 Solar.
- 답을 바로 알려주지 말고, 한 번에 하나씩 질문을 던져 스스로 생각하게 해줘
  (예: "왜 그렇게 생각해요?", "근거는 뭘까요?", "다른 관점도 있을까요?")
- 학생은 닉네임만으로 쓰고, 교사는 학생별 대화 내용을 볼 수 있게 해줘
```

[실습] (09:35–10:00)
1. 짓다에서 새 프로젝트를 만든다(도구 이름·목적 입력).
2. AI 채팅에 위 요청을 넣고, 다룰 주제(직접 쓴 문장이나 넣을 PDF·링크)를 함께 넣는다.
3. 라이브 미리보기에서 학생 역할로 짧게 대화해 본다.
4. AI가 답을 바로 주지 않고 질문으로 되묻는지 확인한다. 답을 바로 줘 버리면 "답을 바로 주지 말고 반드시 질문으로 되묻게 해"를 더 강하게 붙여 다시 요청한다.

#### [핵심 개념 · 대화 평가와 등급] (10:00–10:10)
[강사 멘트] "이제 대화를 '평가'하는 기능을 붙입니다. 학생 답변을 다섯 가지 관점으로 봐요 — 개념을 이해했는지, 예시를 잘 드는지, 논리를 잘 펴는지, 자기 생각을 돌아보는지, 스스로 더 파고드는지. 이 다섯 가지로 점수가 쌓이면 등급이 올라갑니다. 입문 단계에서 시작해서 점점 높은 단계로요. 교사 화면에서는 학생별 등급과 점수가 실시간으로 보이고요."

**[화면 · 짓다 AI 채팅에 이어서 요청]**

```text
학생 답변을 다섯 가지 관점으로 평가해줘:
개념 이해 · 예시 활용 · 논리 전개 · 자기 인식 · 능동적 탐구

```

[실습 · 제작] (10:10–10:30)

2. 라이브 미리보기에서 평가 점수와 등급 표시가 뜨는지 확인한다. 어긋나면 "이렇게 바꿔줘"로 다시 요청한다.

[실습 · 테스트] (10:40–10:55)

2. **짧고 성의 없는 답변**도 넣어 보며 튜터가 어떻게 다시 질문하는지 확인한다.

### 마무리 (공통 · 10:55–11:00)
[강사 멘트] "다들 도구 v1이 처음부터 끝까지 한 번은 돌았나요? 완벽하지 않아도 괜찮습니다. 오늘 목표는 '작동하는 하나'였으니까요. 지금 만든 걸 짓다 갤러리에 올리고, 코들에 한 줄 회고를 남겨 주세요. 이게 다음 차시로, 그리고 본선으로 이어집니다."

[진행] 도구 v1을 짓다 갤러리에 공개하고 회고를 코들에 기록하도록 안내. [체크] 트랙 A: 채점→힌트→(원하면)해결 방법 한 흐름 동작 / 트랙 B: 답 대신 유도 질문+대화 평가·등급 동작.

[전환] "바로 이어지는 2차시에서는 이 도구가 '학생한테 내놔도 되는가'를 봅니다. 잘못된 답, 주제 이탈 같은 걸 막는 안전장치를 붙일 거예요."

## 4. 강의 가이드라인 (이 차시 특화)
- **강조점**: 기능의 개수가 아니라 '한 흐름이 끝까지 도는 도구 하나'. 트랙 A는 '정답을 그대로 주지 않는다', 트랙 B는 '답을 바로 주지 않고 질문을 던진다'가 각 트랙의 핵심 철학. 코드가 아니라 '무엇을·어떤 규칙으로'를 정하는 게 오늘의 일.
- **피해야 할 것**: 코드를 설명·받아쓰게 하는 강의(오늘은 짓다에 말로 요청). 규칙(정답 안 주기 / 답 대신 질문)을 요청에서 빠뜨리는 것. 미리보기로 확인 안 하고 넘어가는 것.
- **톤**: 비전공·저경험 교사 배려. 용어는 처음 나올 때 1줄로 풀고 화면은 크게·천천히. "코딩 못 해도 됩니다"를 반복.
- **시간 관리**: 실습 시간(트랙 A 채점·힌트 요청, 트랙 B 대화 튜터 제작·테스트)은 사수. 지연 시 부가 설명부터 줄인다. 트랙 B는 반별 진도 편차를 코들 대시보드로 상시 확인.
