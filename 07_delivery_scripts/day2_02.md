## 4. 강의 가이드라인 (이 차시 특화)
- **강조점**: 안전장치는 '기능'이 아니라 '교실에 내놓을 수 있는가'의 최소 조건. 검증은 반드시 '내가 먼저 나쁜 질문을 던지는' 방식으로. 트랙 A는 '틀린 답을 자신 있게 말하는 것이 가장 위험', 트랙 B는 '거절 메시지는 다시 초대하듯'.
- **피해야 할 것**: 검증을 눈으로만 보고 넘어가기(반드시 로그). 규칙을 너무 세게 걸어 정상 질문까지 막기.
- **톤**: 1시간 압축 차시. 진단→작성→검증 리듬을 빠르게. 설명 짧게, 손은 학습자.
- **시간 관리**: 검증(11:40–11:55) 시간을 사수. 지연 시 규칙 다듬기 설명부터 줄인다. 트랙 B 2개 반 진도 편차를 코들 대시보드로 확인.

## 5. 실습 지원 · 트러블슈팅
| 상황 | 대응 |
|------|------|
| 라이브 미리보기가 안 뜸 | 새로고침 → 짓다에 마지막 요청 다시 보내 재생성 유도 |
| 짓다가 요청을 오해해 엉뚱하게 반영 | 한 번에 하나씩·짧고 명확한 문장으로 다시 요청 |
| 거절 규칙이 너무 세서 정상 질문까지 막힘 | 정상 질문 세트로 함께 테스트, 짓다에 "정상 질문은 통과시켜줘"로 완화 요청 |
| 우회·탈옥 요청에 규칙이 무너짐(B) | 짓다에 거절 규칙을 더 강하게 요청, 대표 우회 문구로 반복 검증 |
| 튜터가 사실은 틀린 답을 자신 있게 냄(A) | 불확실 시 단정 금지·"선생님께 확인" 안내 규칙을 짓다에 명시 요청 |
| 검증을 눈으로만 보고 넘어감 | 미리보기 입력·응답을 코들 로그로 남겨 문제 응답을 기록·재현 |
| Solar 응답 실패·오류 | 잠시 후 재시도 → 짓다에 마지막 요청 다시 보내기 → 강사 안내 |
| 다수 동시 검증으로 응답 지연 | 조별 순차 검증으로 입력 시점 분산 |
| 나쁜 질문이 잘 안 떠오름 | 강사 준비 예시 세트 제공, 옆 사람 질문 교환 |
| 일찍 끝난 팀(심화 미션) | A: 편향 표현 검증 케이스 추가 / B: 우회 문구를 바꿔가며 규칙 견고성 재검증 |

## 6. 예상 질문 · 답변
| 질문 | 답변 |
|------|------|
| "규칙을 넣었는데 정상 질문까지 막혀요." | 규칙이 과해서 그렇습니다. 정상 질문 세트로 테스트하며 표현을 완화하세요. 차단과 통과의 균형을 맞추는 과정입니다. |
