## 0. 이 차시 한눈에
- **목표**: 본인 수업자료를 Colab에서 Document Parse로 구조화하고 Information Extract로 핵심 정보만 JSON으로 뽑아낸다.
- **산출물**: 본인 수업자료 1건의 구조화 결과 + 핵심 추출 JSON 파일(코들 보드 업로드).
- **앞 차시 연결**: 3차시에서 Solar LLM의 원리(입력→토큰→응답)를 배웠다. 오늘은 그 LLM에 "먹일 데이터"를 만든다.
- **다음 차시 연결**: 오늘 만든 JSON이 5차시 보조 agent(챗봇)의 입력. "문서→구조화→핵심 추출→챗봇" 파이프라인의 앞 두 칸을 오늘 완성한다.

## 3. 강사 스크립트 (핵심 순간 대본)

### 오프닝
[강사 멘트] "선생님들, 지금 책상 위에 있는 시험지 PDF 한번 떠올려 보세요. 우리 눈에는 완벽한 자료죠. 그런데 AI 입장에서 이건 그냥 '그림 뭉치'예요. 문항이 몇 번인지, 배점이 몇 점인지 AI는 하나도 모릅니다. 오늘 우리가 할 일은 이 PDF를 AI가 읽을 수 있는 '데이터'로 바꾸는 겁니다."
(talking point) 3차시에서 배운 Solar LLM을 상기 — 아무리 좋은 모델도 입력이 정리 안 되어 있으면 못 쓴다.

### [핵심 개념] 파이프라인
[화면] "문서 → 구조화(Document Parse) → 핵심 추출(Information Extract)" 3칸 다이어그램.
[강사 멘트] "오늘 파이프라인은 딱 세 칸입니다. 왼쪽은 우리가 매일 쓰는 문서, 가운데 Document Parse가 이걸 표·문단·수식 단위로 뜯어서 구조를 잡아주고, 오른쪽 Information Extract가 그중에서 우리가 원하는 것만, 예를 들면 문항·배점·핵심 개념만 골라서 JSON으로 뽑아줍니다."
(talking point) 이 세 칸 중 오늘은 왼쪽 두 칸까지. 오른쪽 결과물이 내일 아니라 바로 다음 시간 챗봇 재료다.

### [실습 지시] Document Parse
[실습] 1) 배포된 Colab 노트북에서 "드라이브에 사본 저장"으로 본인 사본을 먼저 만드세요. 2) 첫 셀(API 키 입력)을 실행합니다 — 조별 배정된 키를 붙여넣으세요. 3) 예제 폴더의 `시험지_예제.pdf`를 업로드 셀에 올립니다. 4) Document Parse 실행 셀을 돌리세요. 5) 출력에서 **표가 표 형태로**, **문항 번호가 문단으로** 잡혔는지 눈으로 확인하세요.
[체크] 화면에 표·문단 구조가 뜨면 성공. "표가 깨져 보이는 분?" 거수 확인.
(talking point) 표·수식 많은 자료는 편차가 크다 — 안 되면 깔끔한 단원부터.

### [전환]
[강사 멘트] "자, 구조는 잡혔어요. 그런데 이 결과 그대로는 너무 많죠. 이제 여기서 '내가 진짜 필요한 것'만 뽑아냅니다. 그게 바로 다음 단계 Information Extract예요."

### [실습 지시] Information Extract
[실습] 1) Information Extract 셀로 내려가세요. 2) 추출 스키마에 `문항번호`, `배점`, `핵심개념` 세 필드가 들어 있는지 확인합니다. 3) 실행하면 파싱 결과가 이 세 필드만 담긴 JSON으로 나옵니다. 4) 출력 JSON에서 문항 개수가 실제 시험지와 맞는지, 배점 합이 맞는지 확인하세요.
(talking point) "무엇을 뽑을지"를 정하는 순간이 곧 도구의 목적을 정하는 순간 — 채점 도구면 배점, 개념 학습 도구면 핵심개념.

### [실습 지시] 본인 자료 적용
[실습] 이제 선생님 본인 수업자료 1건으로 처음부터 다시: 업로드→Parse→Extract→나온 JSON을 **코들 보드 "4차시 산출물" 칸에 파일 또는 캡처로 업로드**하세요. 파일명은 `본인이름_수업자료.json`으로 통일합니다.
[진행] 신화준 보조강사 순회 — 저장 완료한 분 체크리스트에 표시.

### 마무리
[강사 멘트] "오늘 만든 이 JSON 파일, 절대 지우지 마세요. 바로 다음 시간에 이걸 챗봇 안에 그대로 집어넣어서, 선생님 자료로만 대답하는 나만의 보조교사를 만듭니다. 오늘은 그 챗봇의 '뇌에 넣을 지식'을 우리 손으로 만든 겁니다."

## 4. 강의 가이드라인 (이 차시 특화)
- **강조점**: (1) PDF≠데이터, 구조화가 전제. (2) "무엇을 뽑을지 = 도구의 목적". (3) JSON은 반드시 저장 — 5차시 직결.
- **피해야 할 것**: 파싱 정확도·벤치마크 수치 자랑 금지(공통 §2). "이걸로 뭘 할 수 있나"만 보여준다. 표·수식 완벽 파싱을 라이브로 무리하게 밀지 말 것 — 안 되면 사전 캡처로 넘어간다.
- **톤**: 코딩 몰라도 셀 실행만 하면 되는 수준으로 안심시킨다. "실행 버튼만 누르면 됩니다."
- **시간 관리**: 실습 3구간(DP·IE·본인자료)이 핵심. 개념(0–8분)이 길어지면 잘라서 실습으로. 지연 시 예제 IE 실습을 축약하고 본인 자료 적용 시간을 사수한다(실습 우선, 공통 §4).

## 5. 실습 지원 · 트러블슈팅
| 상황 | 대응 |
|------|------|
| 참가자 본인 자료 미지참 | 공용 예제 문서로 실습 완료, JSON 산출은 예제로 대체. 쉬는 시간에 개인 자료로 재실행 안내 |
| Document Parse가 표·수식을 못 잡음 | 텍스트 깔끔한 단원 PDF부터. 파싱 결과 육안 검수 후 진행, 실패 부분은 부분 추출로 진행 |
| Colab 사본 안 만들고 원본 편집해 충돌 | "드라이브에 사본 저장" 다시 안내, 배포 링크에서 재발급 |
| API 키 오류·호출 실패 | 조별 키 오타 확인 → 공용 예비 키 안내 → 그래도 실패 시 사전 캡처 결과로 실습 흐름 유지 |
| 공용 키 레이트 리밋(동시 호출 폭주) | 호출 시점 분산 — 강사 시연 후 조를 A/B로 나눠 순차 실행 |
| JSON 저장 누락 | 신화준이 체크리스트로 실시간 확인, 미저장자 코들 보드 업로드까지 1:1 동행 |
| IE JSON 필드가 비어 나옴 | 파싱 결과가 비었는지 먼저 확인 → 문서 페이지 범위·스키마 필드명 점검 |

| 질문 | 답변 |

| "손글씨·스캔 시험지도 되나요?" | 인쇄체·디지털 PDF가 가장 잘 됩니다. 스캔·손글씨는 편차가 커요. 오늘은 잘 되는 유형부터, 실무 적용은 문서 품질을 올려서 쓰시길 권합니다. |

| "JSON에서 뽑는 필드를 제가 바꿔도 되나요?" | 바로 그게 핵심입니다. 필드를 바꾸는 게 곧 도구 목적을 바꾸는 거예요. 채점용이면 배점, 개념학습용이면 핵심개념을 넣으세요. |
| "코딩을 못하는데 이걸 따라갈 수 있을까요?" | 오늘은 셀 실행 버튼만 누르면 됩니다. 코드를 짜는 게 아니라 돌리는 거예요. 옆에 보조강사가 상시 있습니다. |
