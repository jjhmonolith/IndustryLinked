## 0. 이 차시 한눈에
- **목표**: Solar API를 직접 호출해 '정보 교과 보조교사' 페르소나를 세우고, 4차시 JSON을 넣어 내 수업자료 기반으로만 답하는 챗봇 MVP를 만든다.
- **산출물**: 자기 수업자료 기반 보조 agent(챗봇) MVP + 코드/대화 캡처(코들 업로드).
- **앞 차시 연결**: 4차시에서 만든 수업자료 JSON이 오늘 챗봇의 지식 재료. "문서→구조화→핵심 추출→챗봇"의 마지막 칸을 오늘 채운다.
- **다음 차시 연결**: 6차시에서 이 챗봇을 '수업 도구 4요소'로 진단하고, 7차시에서 안전장치를 입힌다. 오늘 MVP가 그 대상이다.

## 3. 강사 스크립트 (핵심 순간 대본)

### 오프닝
[강사 멘트] "방금 4차시에서 만든 JSON, 다들 코들에 저장하셨죠? 이번 시간엔 그 파일이 진짜 챗봇으로 살아납니다. 완벽한 제품을 만드는 게 아니에요. 오늘 목표는 딱 하나 — '내 수업자료로 대답하는 챗봇이 한 번이라도 제대로 돌아가게' 하는 겁니다. 이걸 MVP, 최소 동작본이라고 부릅니다."
[화면] 완성 챗봇에 "1단원 핵심 개념 알려줘"라고 묻고 자료 기반으로 답하는 데모 30초.

### [핵심 개념] system / messages 구조
[강사 멘트] "Solar API에 말을 걸 때는 두 종류의 메시지가 있어요. 하나는 `system` — 챗봇의 성격과 규칙을 정하는 자리입니다. '너는 정보 교과 보조교사야'라고 여기서 못 박아요. 다른 하나는 `messages` — 실제 사용자와 챗봇이 주고받는 대화입니다."
(talking point) system=한 번 정하는 인격/규칙, messages=매번 오가는 대화. 이 구분이 오늘의 핵심.

### [실습 지시] 1단계 — 페르소나 설정
[실습] 1) Colab 노트북 사본을 만들고 API 키 셀을 실행하세요(조별 키). 2) `system` 프롬프트 셀에 아래 페르소나를 넣습니다(수정 가능). 3) `messages`에 "삼각형의 내각의 합은?" 같은 질문을 넣고 호출 셀을 실행하세요. 4) 응답 말투가 '보조교사'다워졌는지 확인하세요.

```python
# system 프롬프트 예시 — 정보 교과 보조교사 페르소나
system_prompt = """당신은 중등 '정보' 교과의 보조교사입니다.
- 학생이 스스로 생각하도록 정답을 바로 주지 말고 힌트와 단계를 안내합니다.
- 쉬운 말로, 존댓말로, 3~4문장 이내로 설명합니다.
- 모르는 내용은 지어내지 말고 "그 부분은 확실하지 않습니다"라고 말합니다."""

response = client.chat.completions.create(
    model="solar-pro",
    messages=[
        {"role": "system", "content": system_prompt},
        {"role": "user", "content": "1차시 핵심 개념을 알려줘"},
    ],
)
print(response.choices[0].message.content)
```

[체크] 응답이 존댓말·힌트형으로 나오면 1단계 성공. "말투 바뀐 분?" 거수.

### [전환] 1단계 → 2단계
[강사 멘트] "그런데 지금 이 챗봇, 말투는 보조교사인데 문제가 하나 있어요. 우리 수업자료를 전혀 모릅니다. 그냥 일반 지식으로 답하죠. 3차시에서 배운 '환각' 기억나시죠? 자료를 안 주면 그럴싸하게 지어냅니다. 그래서 이제 아까 만든 내 JSON을 챗봇에게 '이 안에서만 답해'라고 쥐여줄 겁니다."

### [실습 지시] 2단계 — 내 자료 삽입
[실습] 1) 4차시에서 만든 본인 JSON 파일을 노트북에 업로드하세요(미보유자는 공용 예제 JSON). 2) `system` 프롬프트에 "아래 [자료] 범위 안에서만 답하고, 자료에 없으면 '자료에 없습니다'라고 답하라"는 규칙과 함께 JSON 내용을 붙여넣습니다. 3) 토큰이 길어지면 `핵심개념`·`문항` 등 필요한 필드만 넣으세요. 4) 자료 안에 있는 개념을 물어보고, 자료 밖 질문(예: "오늘 점심 뭐 먹지?")도 던져보세요.
[체크] 자료 안 질문엔 근거 있게, 자료 밖 질문엔 "자료에 없습니다"에 가깝게 나오면 성공.

### [실습 지시] 개인 테스트
[실습] 선생님 수업자료와 관련된 질문 2개, 전혀 무관한 질문 1개를 던져 응답을 비교하세요. 범위를 벗어난 답이 나오는 경우도 그대로 캡처해 두세요 — 7차시 안전장치 실습에서 이걸 씁니다.
(talking point) 지금 범위 이탈이 보여도 정상 — 오늘은 현상 확인까지, 막는 건 7차시.

### 마무리
[강사 멘트] "축하합니다. 방금 선생님들은 '내 수업자료로 대답하는 나만의 보조교사'를 직접 만들었어요. 코들에 코드랑 대화 캡처를 올려주세요. 아직 완벽하진 않죠? 자료 밖 질문에 엉뚱하게 답하기도 하고요. 그 빈틈을 다음 시간부터 하나씩 채웁니다."
[진행] 신화준 순회 — 코들 업로드 완료 체크.

## 4. 강의 가이드라인 (이 차시 특화)
- **강조점**: (1) system=인격/규칙, messages=대화라는 구조. (2) 1단계(페르소나만) vs 2단계(자료 근거)의 체감 차이. (3) 자료를 주면 환각이 줄어든다 — 3차시 원리와 연결. (4) 목표는 MVP.
- **피해야 할 것**: Solar 성능·벤치마크 자랑 금지(공통 §2). 완벽한 챗봇을 요구해 시간을 넘기지 말 것 — "한 번 돌면 성공". 범위 이탈을 오늘 다 막으려 들지 말 것(7차시 몫).
- **톤**: "코드를 이해 못 해도 됩니다, 붙여넣고 실행하면 됩니다." 완성했을 때 성취감을 크게 짚어준다.
- **시간 관리**: 2단계 실습(15:33–15:48)이 핵심 — 사수. 개념 설명이 길어지면 잘라서 실습으로. 지연 시 개인 테스트 질문 수를 줄이되 2단계 완성은 지킨다(실습 우선, 공통 §4).

| 4차시 JSON 미보유/저장 실패 | 공용 예제 JSON 즉시 제공, 실습 지속. 쉬는 시간 개인 자료로 재실행 권유 |
| 프롬프트가 길어 토큰 초과·응답 저하 | JSON에서 `핵심개념`·`문항` 등 핵심 필드만 남겨 축약, 불필요 필드 삭제 안내 |
| 자료 밖 질문에도 답해버림(범위 이탈) | 오늘은 현상만 캡처. "이건 7차시 안전장치로 막습니다"로 흐름 보호 |
| Solar API 키 오류·호출 실패 | 키 오타 확인 → 공용 예비 키 → 실패 시 사전 캡처 데모로 흐름 유지 |
| 공용 키 레이트 리밋(동시 호출) | 조별 호출 순번표대로 순차 실행, 강사 시연 후 조 A/B 분산 |
| system과 user에 자료를 잘못 넣어 응답 이상 | JSON은 `system`에, 질문은 `user`에 — 위치 재확인 |
| 코드 오류로 셀이 안 돌아감 | 사전 배포 노트북 셀 원본과 대조, 수정 셀 초기화 후 재실행. 보조강사 1:1 |
| 응답이 영어로 나옴 | system에 "한국어 존댓말로 답하라" 한 줄 추가 안내 |
