## 0. 이 차시 한눈에
- **목표(1줄)**: LLM이 "확률 기반 자동완성"임을(토큰화→다음 단어 예측→환각) 설명하고, 같은 한국어 프롬프트로 Solar와 해외 모델 응답 차이를 체감한다.
- **산출물**: Colab 접속 + Solar API 키 정상 호출 확인(테스트 셀 1회 실행) / Solar vs 해외 모델 비교 소감 코들 메모(1~2줄).
- **앞 차시 연결**: 오전에 시연한 도구가 쓰는 AI가 실제로 어떻게 답을 만드는지 원리로 파헤친다.
- **다음 차시 연결**: 4차시(Document Parse + Information Extract)에서 '내 자료를 데이터로' 바꾼다. 여기서 점검한 Colab/API 환경이 그 실습의 기반.

## 3. 강사 스크립트 (핵심 순간 대본)

### 오프닝 — 경험 공유
[강사 멘트] "안녕하세요, 업스테이지 남대현입니다. 본격적인 원리 이야기 전에 여쭤볼게요. 요즘 챗봇 AI, 수업 준비하실 때 써 보신 분 손 들어 주시겠어요? (거수) 그럼 그중에, AI가 자신 있게 틀린 답을 준 적 있는 분?"
[강사 멘트] "네, 많으시죠. 오늘은 바로 그 '왜 AI가 당당하게 틀리는가'를 원리로 이해하는 시간입니다. 이걸 알고 나면, 오전에 보신 도구들이 왜 그렇게 설계됐는지 딱 이해가 되실 거예요."

### [핵심 개념] 토큰화
[강사 멘트] "AI는 우리처럼 문장을 통째로 읽지 않습니다. '나는 학교에 간다'를 '나 / 는 / 학교 / 에 / 간다' 같은 작은 조각으로 쪼개요. 이 조각을 '토큰'이라고 합니다."
(수식·내부 구조는 배제. '단어를 조각으로 나눠 숫자로 바꾼다' 수준의 직관만 전달)

### [핵심 개념] 다음 단어 예측 ('확률 기반 자동완성' 비유)
[강사 멘트] "그럼 AI는 이 조각들을 보고 뭘 할까요? 딱 하나입니다. '다음에 올 조각으로 가장 그럴듯한 게 뭘까'를 확률로 고르는 거예요. 여러분 휴대폰 자판의 자동완성, 그걸 어마어마하게 키운 것 — 그게 LLM의 본질입니다."
[강사 멘트] "'대한민국의 수도는' 다음에 '서울'이 나오는 건, AI가 서울을 '알아서'가 아니라 그 자리에 서울이 올 확률이 압도적으로 높기 때문입니다. 이해가 아니라 확률 계산이에요."

### [핵심 개념] 환각
[강사 멘트] "여기서 핵심이 나옵니다. AI는 '그럴듯한 다음 조각'을 고를 뿐, '이게 사실인가'는 확인하지 않아요. 그래서 그럴듯하지만 틀린 답 — 이걸 '환각'이라고 합니다. 환각은 고장이 아니라, 확률로 자동완성하는 원리상 당연히 생기는 겁니다."
(이 지점을 7차시 안전장치의 필요성으로 연결 — "그래서 우리가 오전에 본 챗봇처럼 '자료 범위 안에서만 답하게' 묶어 두는 겁니다")

### [시연] 국내외 모델 비교
[화면] Solar와 해외 모델에 동일 한국어 프롬프트 입력(사전 검증된 것만 라이브, 미검증은 캡처).
[강사 멘트] "이제 같은 질문을 Solar와 해외 모델에 똑같이 던져 보겠습니다. 먼저 우리 문화 맥락이 들어간 질문 — 한국식 시험 문제나 우리말 뉘앙스가 필요한 질문이요. 어느 쪽이 우리 교실 맥락을 더 자연스럽게 잡는지 직접 보세요."
[강사 멘트] "오해 없으셨으면 합니다. '해외가 나쁘다'는 게 아니에요. 한국어와 우리 교과 맥락, 그리고 데이터가 국내에 남는다는 점에서 Solar가 어떤 강점을 갖는지를 체감하시는 게 목적입니다."
[실습] 코들 메모에 1~2줄 — "두 응답을 비교해 보니 어떤 차이가 느껴졌는지."

### [실습 지시] Colab·API 키 사전 점검 (신화준 주도)
[강사 멘트] "다음 시간부터는 여러분이 직접 이 AI를 불러 씁니다. 그래서 지금, 오후 실습 환경을 미리 딱 한 번 켜 보겠습니다. 여기서 문제를 잡아 두면 다음 시간이 훨씬 수월해집니다."
[실습] (1) 배포된 Colab 노트북 링크 열기 → 사본 저장 → 런타임 연결. (2) 안내된 자리에 Solar API 키 입력 → 테스트 셀 1회 실행 → 정상 응답 확인.
[진행] 신화준·보조 순회. 키 오류·런타임 실패 팀 우선 지원. 다수 동시 호출 시 조별 순차로 분산.
[체크] 각 좌석 테스트 셀 응답 성공 여부 확인 — 실패자는 이 차시 안에 해결(4차시로 넘기지 않는다).

### 마무리
[강사 멘트] "정리하면, LLM은 확률로 다음 말을 잇는 아주 똑똑한 자동완성이고, 그래서 가끔 틀리는 건 원리상 자연스러운 일입니다. 그리고 Solar는 한국어와 우리 교실 맥락, 데이터 주권 면에서 학교에 잘 맞는 선택이라는 것 — 이 두 가지만 기억해 주세요."
[강사 멘트] "환각을 줄이는 가장 확실한 방법 하나가 '내가 준 자료 안에서만 답하게 하는 것'인데요, 그 자료를 어떻게 준비하는지가 바로 다음 시간입니다."

## 4. 강의 가이드라인 (이 차시 특화)
- **강조점**: '확률 기반 자동완성' 비유로 환각을 원리상 당연한 것으로 각인 → 7차시 안전장치 필요성의 복선. Colab/API 키 점검을 이 차시 안에 반드시 완료.
- **피해야 할 것**: 수식·아키텍처 심화 / "해외 모델이 나쁘다"식 비교 / 벤치마크 수치 자랑 / 미검증 기능 라이브 시연.
- **톤**: 어려운 원리를 일상 비유로. 교사들의 생성형 AI 경험을 존중하고 그 경험에서 원리로 끌어올린다.
- **시간 관리**: 원리 설명은 20분 이내. Colab/API 점검 10분은 사수 — 여기서 못 잡으면 오후 실습 전체가 밀린다. 지연 시 모델 비교 라운드를 줄이고 환경 점검을 지킨다.

## 6. 예상 질문 · 답변
| 질문 | 답변 |
|------|------|
| "AI가 틀린 답을 주면 책임은 누가 지나요?" | 그래서 이 연수가 안전장치를 배웁니다. AI는 보조이고 최종 확인은 교사입니다. 자료 범위 제한과 사후 점검으로 위험을 줄입니다. |
| "환각을 완전히 없앨 수 있나요?" | 원리상 완전히 없애긴 어렵습니다. 대신 '자료 범위 안에서만 답하게' 묶으면 크게 줄일 수 있고, 그 방법을 4·5차시에서 만듭니다. |

| "API 키가 계속 오류인데 실습을 못 하나요?" | 공용 예비 키가 있고, 최악의 경우 폴백 방식으로 진행합니다. 신화준 선생님이 지금 바로 옆에서 잡아드립니다. |
| "토큰이 정확히 뭔가요?" | 문장을 AI가 다루기 쉽게 쪼갠 작은 조각입니다. 오늘은 '문장을 조각으로 나눠 확률로 잇는다' 정도만 이해하시면 충분합니다. |
