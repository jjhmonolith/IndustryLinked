# 코들 플랫폼을 연수 운영에 활용하기 — 기능 분석과 차시 매핑

> 작성일: 2026-06-02
> 목적: 구글독스·패들릿 대신 코들 자체 기능을 연수 운영에 활용한다. **이중 효과** — (a) 기록·공유·피드백 도구를 일원화, (b) 교원들이 *자기가 가르치게 될 도구*를 학습자로서 체험.

## 1. 코들 활동 유형 — 연수 적합성 분석

| 활동 | 기능 요지 | 연수 적합성 | 대체 대상 |
|------|----------|-------------|-----------|
| **보드** | 자유 의견 카드 + 댓글, 5초 간격 실시간 업데이트, 이미지/파일 첨부, 실시간 참여도 분석 탭 | ★★★ 최고 | 패들릿, 구글독스 회고 |
| **활동지** | 정형 양식 입력(텍스트·표·체크), 1GB 파일 업로드, 이미지 삽입 | ★★★ | 구글독스 양식 작성 |
| **퀴즈** | 객관식·서술형, AI 자동 생성, 답안 빠른 확인, (4월~) 서술형 AI 채점 | ★★ | 간단한 투표·체크 |
| **공부방** | 틀린 문제 맞을 때까지 반복 | ☆ 연수 부적합 | — |
| **코답** | 코드 없이 데이터 분석·시각화 | ☆ 본 연수 외 | — |
| **코드(파이썬)** | 자동채점 + AI 튜터 | (체험 대상) | — |
| **동영상** | 인솔 모드 — 학생이 교사 재생 상태 따라감 | ★ 일부 활용 | — |
| **학습 분석 / 기상캐스터** | 학생 진행도·정체·접속 실시간 모니터링 | ★★ 강사용 | 출석·진도 점검 |

### 핵심 결론

- **보드 = 패들릿 대체**: 자유 토론·피드백·갤러리에 가장 적합. 실시간성·댓글·이미지 첨부가 모두 갖춰짐.
- **활동지 = 구글독스 양식 대체**: 정형 양식(워크시트·기획서·체크리스트)에 가장 적합.
- **퀴즈 = 가벼운 투표·확인 도구**: 모델 선택, 우수사례 투표, 만족도 1문항 등에 활용.
- **기상캐스터 = 강사 운영 도구**: 50명 분반에서 누가 막혔는지 감지.

## 2. 활용 원칙

1. **연수 자체가 코들 운영 연습**: 교원이 "학생 시점"으로 코들을 사용하면, 11-13차시 바이브코딩 때 자기 도구의 4요소가 어떻게 구현되는지 자연스럽게 체득.
2. **짓다 갤러리는 그대로 유지**: 짓다 결과물 공유는 짓다 갤러리(4·13·14차시). 코들 보드와 역할 분리.
3. **이중 사용 금지**: 한 차시에 코들 보드 + 활동지 + 퀴즈를 동시에 쓰지 않는다. 차시별 1-2개로 단순화.
4. **사전 준비**: 강사가 연수 시작 전 각 차시 활동을 코들 교실에 미리 등록한다.

## 3. 차시별 매핑

| 차시 | 기존(구글독스/패들릿) | 변경 — 코들 활동 | 비고 |
|------|----------|--------|------|
| 1 | 회고 한 줄 | **보드** — "내가 풀고 싶은 수업 문제 한 줄" | 실시간으로 동료 글 보임 → 동기부여 |
| 2 | 팀별 좋은점·아쉬운점·바꾸고 싶은 점 | **보드** — 3색 카드(좋은점/아쉬운점/바꾸고 싶은 점) 팀별 게시 | 패들릿 가장 강한 대체 지점 |
| 3 | 4요소 분해 워크시트 | **활동지** — 4요소 표 + "내가 바꾸고 싶은 점" 매핑 칸 | 정형 양식의 본격 등장 |
| 4 | 짓다 갤러리 + 회고 | 짓다 갤러리 그대로 + **보드** — "5차시 이후 무엇이 필요한가" 한 줄 | 짓다 결과물은 갤러리, 회고는 보드 |
| 5 | "Solar로 만들고 싶은 것 한 줄" | **보드** — 동일 | 합반 보드 → 트랙 간 아이디어 교류 |
| 6 | 선택 기준 시트 + 1차 모델 결정 | **활동지** — 선택 기준 우선순위(1-5) + **퀴즈** — "내 MVP 1차 모델" 객관식 | 활동지+퀴즈 조합 |
| 7 | 가드레일 초안 + 우회 시도 결과 | **활동지** — 시스템 프롬프트 작성 + 우회 시도 5건 결과 | 텍스트 작성에 적합 |
| 8 | MVP 구조 다이어그램 | **보드** — 다이어그램 이미지 업로드 | 이미지 첨부 + 동료 작품 즉시 관람 |
| 9 | 한계·결정사항 | **활동지** — "내 도구의 한계 1가지 + 다음 결정" | 짧고 정형 |
| 10 | MVP v0.5 구성요소 | **활동지** — 구성요소 체크리스트 | 11차시 기획서 입력으로 이어짐 |
| 11 | 기획서 1쪽 | **활동지** — 기획서 양식 1쪽 (9개 항목) | 활동지가 가장 빛나는 차시 |
| 12 | 작동 안 하는 1가지 | **보드** — "지금 막힌 지점" 카드 (멘토 라이브 대응용) | 멘토가 보드를 보고 순회 |
| 13 | 14차시 시연 시나리오 | **활동지** — 시연 시나리오 양식 | |
| 14 | 동료 피드백 (패들릿 대체) + 우수사례 추천 | **보드** — 4항목 댓글(인상/답답/제안/궁금) + **퀴즈** — 트랙별 우수사례 투표 | 패들릿 가장 강한 대체 지점 |
| 15 | 회고 5개 항목 + 한 줄 평 | **활동지** — 회고 5개 항목 + **퀴즈** — 만족도 1문항(객관식) | 마지막 회고는 정형 |

## 4. 코들 운영 사전 준비 체크리스트

- [ ] 트랙별 교실 1개씩 (총 2개) — 트랙 A 교실, 트랙 B 교실
- [ ] 교실 입장 링크/코드 사전 안내 (1차시 직전)
- [ ] 차시별 활동 사전 등록 — 15개 차시 × 평균 1-2 활동 = 약 20-25 활동
  - 보드(자유 게시): 약 6-7개
  - 활동지(양식): 약 8-9개
  - 퀴즈: 약 3개
- [ ] 활동지 양식 사전 디자인 (가장 시간 소요): 3차시(4요소), 6차시(선택기준), 7차시(가드레일), 10차시(구성요소), 11차시(기획서), 13차시(시연), 15차시(회고)
- [ ] 보드 카드 색상·라벨 통일 (좋은점=초록, 아쉬운점=노랑, 바꾸고 싶음=빨강)
- [ ] **실시간 분석/기상캐스터**는 유료 플랜 — 운영팀과 라이선스 협의 (이미 사전 준비 가정이지만 명시 필요)
- [ ] 학습 분석 페이지를 강사용 보조 화면으로 사용 (강사 노트북 1대 띄워두기)

## 5. 이중 효과 — "학습자가 코들 학생 시점을 체득"

연수 자체에서 교원이 **학생으로 코들을 사용**하면 다음과 같은 학습이 자동으로 일어남:

| 코들 체험 | 11-13차시 바이브코딩 자연 연결 |
|-----------|--------------------------------|
| 보드에 글을 올리고 댓글 받기 | 트랙 B "학생 챗봇 화면" 설계 시 입력·표시 UX 감각 |
| 활동지에 정형 양식 입력 | 트랙 A "문제 화면" 설계 시 입력 양식 감각 |
| 퀴즈 객관식·서술형 풀이 | 자기 도구의 평가 형식 결정 시 |
| 기상캐스터로 진도 보이는 느낌 | 트랙 공통 "교사 대시보드" 설계의 영감 |

3차시(수업도구 구조 이론)에서 "**여러분이 지금까지 *학생으로* 코들을 쓴 경험**을 4요소로 분해해보자"고 짚어주면 효과 극대화.

## 6. 변경 시 운영 효과·위험

### 효과

- **도구 일원화**: 구글독스 시트 링크 관리·접근 권한 문제 사라짐
- **체험-학습 일치**: 교원이 학생 시점으로 운영 도구를 직접 사용
- **실시간성**: 강사가 학습자 진도·정체를 즉시 파악(기상캐스터)
- **운영 후 자료 보존**: 교실 단위로 모든 회고·산출물이 한 곳에 남음 → 사후 보고·바이브톤 입력으로 그대로 사용

### 위험

- **사전 등록 부담**: 약 20-25개 활동을 강사가 미리 만들어야 함. 연수 1-2주 전 작업 필요.
- **장애 위험**: 코들 자체 장애 시 회고·기록 전체가 멈춤. 백업으로 종이 양식 1세트 비치 권장.
- **학습자 입장 지연**: 1차시 도입에 5분 추가 → 사전 안내문에 "초대 코드 미리 입장" 안내 강화.
