# 컨소시엄 역할 분담 — 업스테이지가 운영할 차시 권장

> 작성일: 2026-06-01
> 전제: 팀모노리스 = 코들·짓다 운영사 / 업스테이지 = Solar·독파모·Document AI 개발사 / 학회 = 1차시 훈화 일부

## 분담 판단 기준

1. **독자 지식 우위** — 그 회사만이 가진 내부 정보·노하우가 있는가?
2. **연수 목표 직결성** — 연수 목표 4개 중 *"독파모 개발 목적·의의 인식"*과 *"여러 LLM 모델 특성 이해"*에 직접 기여하는가?
3. **신뢰 효과** — 개발사가 직접 설명할 때 교원이 더 신뢰·동기부여를 받는가? (특히 5·6·7차시)
4. **균형** — 업스테이지가 너무 많이 맡으면 자사 제품 설명으로 흐를 위험이 있으므로 적정선 유지

## 요약 — 업스테이지 담당 분량

- **단독 운영**: 5, 6, 7차시 (3차시 = 150분)
- **공동 운영**: 1차시(일부), 8차시, 9-10차시 (트랙 분기되어 트랙당 다름)
- **게스트**: 14-15차시 심사
- **합계**: 약 4-5차시 분량 (전체 15차시 중 ~30%)

## 분량 적정성 검토

- 업스테이지 단독 5-7차시 = Day 1의 중반 블록. **"기술 이론" 블록을 통째로 업스테이지가 맡는 구조**로 자연스럽게 형성된다.
- 단, **연속 3차시(150분)는 길다** → 5-6-7차시 사이에 짧은 핸즈온(짓다 미니 실습)을 끼워 넣어 강의-실습 리듬 유지 필요 (운영안 설계 시 반영).

## 업스테이지에게 전달할 콘텐츠 가이드

연수 원칙 ("하면 안 될 것")을 사전에 반드시 공유:

- ❌ 목적 없이 자세한 프롬프트 엔지니어링
- ❌ Document AI를 트랙 활용 없이 시연만 하기
- ❌ Solar 자체 자랑 (벤치마크 수치 나열 등)
- ❌ 이론 슬라이드 다수

대신 권장:

- ✅ **"교실에서 이런 일이 벌어진다 → Solar는 이렇게 다룬다"** 시나리오 기반
- ✅ **다른 모델로 시연 → Solar로 시연 → 차이 체감**
- ✅ **가드레일 프롬프트 패턴**을 손에 잡히는 템플릿으로 제공
- ✅ 슬라이드 < 라이브 시연 < 교원 직접 입력

## 컨소시엄 발송용 한 문장 요약

> "업스테이지에 1차시 일부(독파모 의의), 5·6·7차시 단독, 8차시 공동, 9-10차시 기술 파트, 14-15차시 심사 게스트 역할을 제안. 전체 약 30% 분량. 이론보다 시나리오 기반 시연을 요청."
