## 1. 기준 도구 — 소크룸(Socroom, codle 제공)

소크룸은 **"교실 최적화 AI 수업 도구"**. ChatGPT와 달리 "대화가 항상 수업 주제 안에서 이어진다"는 점이 차별점.

### 1.1 작동 흐름 (3단계)

| 단계 | 교사 | 학생 |
|------|------|------|
| Stage 1 | 몇 가지 항목 입력으로 수업 생성, 링크 전송 | — |
| Stage 2 | (모니터링) | 닉네임으로 접속, AI의 주제 관련 질문에 답하며 학습 |
| Stage 3 | 대화 내역과 학생 순위 확인, 피드백 제공 | — |

➜ "교사 설정 → 학생 참여 → 교사 피드백" 3단계는 **트랙 B의 MVP 흐름을 그대로 차용**할 수 있다.

### 1.2 핵심 설계 원칙

- **"정답을 주지 않는 AI"**: 답을 직접 주지 않고, **학생이 교재를 스스로 찾아보도록 질문**한다 → 자기주도학습 유도
- **주제 범위 제한**: 시스템 프롬프트 + (추정) 교과 자료 RAG로 주제 밖 대화 차단
- **학생 가입 불필요**: 닉네임 입력만으로 참여 → 진입장벽 최소화
- **교사 대시보드**: 모든 대화 내역 열람 → 책임·안전성 확보
- **무료 서비스**

### 1.3 지원 교과

국어·수학·사회·과학·영어·도덕·기술가정·**정보** 등 전과목 지원 → 정보 교과 외에도 응용 사례 풍부.

## 2. 일반화된 "교과범위 RAG 챗봇" 패턴

### 2.1 RAG가 교실에서 필수인 이유

LLM 기반 챗봇의 교육 적용을 가로막는 가장 큰 장벽은 **환각(hallucination)**. RAG는 이를 다음과 같이 해결:

1. **폐쇄적 정보원**: 인터넷 전체 X, **교사가 업로드한 교과 자료만** 검색
2. **출처 추적**: 답변마다 원본 자료를 인용 → 학생·교사 모두 검증 가능
3. **학습 목표 기반 제약**: 시스템 프롬프트가 "이 학습 목표 범위 안에서만 답하라"고 강제

### 2.2 글로벌 사례 — Khan Academy의 Khanmigo

- **소크라테스식 튜터**: 질문에 직접 답하지 않고 "되묻는다"
- **커리큘럼 바운드**: Khan Academy 콘텐츠 라이브러리에 묶임
- **GPT-4 기반 + 파인튜닝 + 가드레일**: K-12 안전 환경
- **1년 만에 6.8만 → 70만 사용자**, 380개 학군 도입 (2023→2024)

➜ 소크룸은 사실상 **"한국 교과서 기반 Khanmigo"**. 연수에서 두 도구를 나란히 시연하면 트랙 B의 가치가 명확해진다.

### 2.3 RAG 챗봇 구축 표준 패턴 (교사용 어휘로 단순화)

```
[1] 자료 준비
    - 교과서/단원 PDF, 학습지, 교사 노트
[2] 자료를 잘게 자르기 (chunking)
    - 보통 페이지·문단 단위
[3] 자료를 벡터(임베딩)로 변환
    - LLM이 검색할 수 있는 형태로
[4] 사용자 질문이 오면
    - 질문도 벡터로 바꿔서 가장 비슷한 자료 조각 찾기
    - 그 조각을 LLM에 같이 넣어서 답변 생성
[5] 답변 + 출처 표시
```

➜ 이 5단계는 **9-10차시 RAG 기술** 수업의 그대로의 골격. 단, "이론은 이름만 알면 충분" 원칙에 따라 **개념 1슬라이드 + 짓다 프롬프트 패턴 위주**로 가야 한다.

## 3. 가드레일 / 안전성 메커니즘 (트랙 B의 핵심)

### 3.1 시스템 프롬프트 기반 가드레일 (가장 단순·효과적)

소크룸과 유사 도구가 공통으로 쓰는 패턴:

```
당신은 [학년]의 [과목] 학습을 돕는 튜터입니다.
다음 자료의 범위 안에서만 답변하세요: [retrieved chunks]
규칙:
1. 학생이 답을 물어봐도 절대 직접 답하지 마세요.
   대신 학생이 자료에서 찾을 수 있도록 질문하세요.
2. 자료에 없는 내용은 "교재에서 확인하기 어렵다"고 답하세요.
3. 욕설/혐오/주제 무관 질문은 정중히 거절하고 학습 주제로 돌리세요.
4. 답변에 자료의 어느 부분을 참고했는지 표시하세요.
```

### 3.2 다층 가드레일 구조

| 계층 | 역할 | 구현 난이도 |
|------|------|-------------|
| L1 입력 필터 | 욕설/위험 질문 사전 차단 | 낮음 (키워드+LLM 분류) |
| L2 RAG 제약 | 자료에 없는 질문은 거절 | 중간 (retrieval threshold) |
| L3 시스템 프롬프트 | 페르소나·금지사항 강제 | 낮음 |
| L4 출력 검증 | 응답을 다시 LLM이 평가 | 중간 (한 번 더 호출) |
| L5 대시보드 모니터링 | 교사가 사후 확인·개입 | 운영 |

➜ 본 연수에서는 **L1·L3·L5**를 중심으로 하되, **L2**(RAG 자체 거절)는 트랙 B의 가장 큰 차별점.

## 4. 트랙 B 학습자 산출물 후보 (바이브톤 시작점)

연수 종료 시 교원이 짓다로 만들 수 있어야 할 도구의 MVP:

- **교사 화면**: 교과서 PDF 업로드 + 학습 목표 입력 + 챗봇 링크 발급
- **학생 화면**: 닉네임 입력 → 챗봇과 대화
- **RAG 백엔드**: Solar API + 임베딩 + 벡터 검색 (짓다에서 라이브러리/플러그인 사용 여부 확인 필요)
- **가드레일**: 시스템 프롬프트 + 자료 밖 거절 + 욕설 필터
- **교사 대시보드**: 학생별 대화 로그 + 자주 묻는 질문 모음

> **검증 필요**: 짓다가 임베딩·벡터DB를 어디까지 지원하는지. 만약 부족하다면 (a) Solar Document AI·임베딩 API 호출 + 간단한 in-memory 검색, (b) Upstage Embeddings + 외부 벡터스토어 연결 중 어느 쪽을 표준화할지 결정 필요. → **업스테이지 협의 항목**

## 5. 차시 설계 시사점

| 차시 | 트랙 B 관점 |
|------|--------------|
| 2차시 (수업도구 체험) | 소크룸 직접 사용 → "왜 대화가 주제 안에서 머무는가?" 가설 세우기 |
| 3차시 (수업도구 구조) | 소크룸 화면을 교사 설정·학생 대화·교사 모니터링 3단계로 분해 |
| 4차시 (일단 만들기) | 짓다로 "교과 자료 한 단원 + 단순 챗봇" 최소 버전 |
| 5-6차시 (Solar/LLM) | 환각 사례 직접 만들기 → RAG가 왜 필요한지 체감 |
| 7차시 (LLM 위험요소) | 가드레일 5계층 중 시스템 프롬프트 작성 실습 |
| 8차시 (Solar API 챗봇) | Solar API로 챗봇 만들기 (RAG 없는 버전) → 한계 체감 |
| 9-10차시 (트랙 기술) | RAG 5단계 + 짓다 프롬프트로 자료 검색 붙이기 |
| 11-13차시 (바이브코딩) | MVP 따라 만들기 → 자기 단원 자료로 커스터마이즈 |

## 6. 위험요소 및 대응

- **위험 1**: 짓다에서 RAG 구축이 기술적으로 너무 어려움
  - 대응 A: **사전 제작된 RAG 템플릿/스타터**를 제공하고 교사는 자료·프롬프트만 바꾸기
  - 대응 B: 업스테이지가 RAG-as-a-service 형태로 제공하는 API가 있다면 그것을 표준화
- **위험 2**: 교과서 PDF 저작권
  - 대응: 연수에서는 공개 학습자료(개정 교육과정 공개자료, 위키)로 시연
- **위험 3**: 학생이 "프롬프트 인젝션"으로 가드레일 우회
  - 대응: 7차시에서 실제 우회 시도 → 실패 → 다층 가드레일 필요성 체험
- **위험 4**: LLM이 정답을 줘버림 ("정답을 주지 않는 AI" 원칙 깨짐)
  - 대응: 시스템 프롬프트 + 출력 검증 + 교사 대시보드 점검

## 7. 트랙 A와 공통 / 차이

| 항목 | 트랙 A | 트랙 B |
|------|--------|--------|
| 학생 활동 | 코드 작성·제출 | 자료 기반 대화 |
| 핵심 기술 | 자동 채점 + LLM 오류 설명 | RAG + 시스템 프롬프트 |
| 가드레일 우선순위 | "정답 코드 주지 말기" | "주제 이탈·정답 직답 막기" |
| 평가 산출물 | 정답률, AI 대화 로그 | 대화 로그, 학습 도달 여부 |
| 공통 4요소 | 학생-교사 / 배부 / 제출 / 대시보드 모두 적용 | 동일 |
