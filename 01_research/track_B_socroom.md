## 1. 기준 도구 — 소크룸(Socroom, codle 제공)

소크룸은 **"소크라테스식(산파법) AI 대화 학습 활동"**이다. ChatGPT처럼 답을 주는 챗봇이 아니라, **직접 답을 주지 않고 유도 질문을 한 번에 하나씩 던져** 학생 스스로 사고를 확장하도록 유도한다.

### 1.1 작동 흐름 (3단계)

| 단계 | 교사 | 학생 |
|------|------|------|
| Stage 1 (설정) | **주제·난이도** 입력으로 활동 생성(주제는 텍스트/PDF/URL, AI가 토픽 자동 생성), 링크 전송 | — |
| Stage 2 (대화) | (실시간 모니터링) | 닉네임으로 접속, AI 튜터의 **유도 질문에 답하며** 다회차 대화 |
| Stage 3 (마무리) | 학생별 등급·점수·대화 내역 확인, 피드백 | 정해진 턴 수 도달 시 마무리 발화 수신 |

➜ "교사 설정(주제·난이도) → 학생 대화 → 교사 확인·피드백" 3단계는 **트랙 B MVP 흐름을 그대로 차용**할 수 있다.

### 1.2 핵심 설계 원칙

- **"정답을 주지 않는 AI"**: 답을 직접 주지 않고, **유도 질문을 한 번에 하나씩** 던져 학생 스스로 생각하게 한다 → 자기주도학습·사고력 유도. (RAG로 "자료 밖을 거절"하는 게 핵심이 아니라, **소크라테스식 질문법**이 핵심.)
- **6단계 질문 프레임**: 튜터의 유도 질문은 **명료화 → 가정 → 증거 → 관점 → 함의 → 메타인지**의 단계를 밟는다.
- **주제 기반 대화**: 교사가 설정한 주제·난이도가 대화의 범위와 깊이를 규정한다. (전체 인터넷을 검색하는 열린 챗봇이 아니라, 정해진 주제 안에서 사고를 파고든다.)
- **학생 발화 5축 자동 채점**: 매 학생 발화를 **개념이해·예시활용·논리전개·자기인식·능동탐구** 5개 항목으로 자동 채점, 점수를 **누적**한다.
- **등급(티어) 시스템**: 누적 점수 비율로 **beginner → learner → explorer → master → sage** 5단계 등급을 부여 → 학생에게 성장 피드백, 교사에게 진척 지표.
- **학생 가입 불필요**: 닉네임 입력만으로 참여 → 진입장벽 최소화.
- **교사 대시보드**: 학생별 등급·점수 실시간 확인 + 개별 대화 열람 → 책임·안전성 확보.

### 1.3 지원 교과

국어·수학·사회·과학·영어·도덕·기술가정·**정보** 등 전과목에 적용 가능 → 정보 교과 외에도 응용 사례 풍부.

## 2. 소크룸의 AI 엔진 구조 (설계팀 참고)

소크룸 대화·채점은 3개의 AI 에이전트로 구성된다(실제 코들 구현 기준, 외부 AI 백엔드에서 실행).

| 에이전트 | 역할 | 산출 |
|---|---|---|
| **tutor** | 소크라테스식 유도 질문(한 번에 하나) | 대화 텍스트 |
| **scorer** | 직전 학생 답변을 5축으로 채점 | 구조화된 점수 |
| **summary** | 마지막 턴의 2~3문장 마무리 | 요약 텍스트 |

### 2.1 대화·채점 흐름

```
[교사] 주제·난이도·최대 턴수 설정 (주제: 텍스트/PDF/URL → AI 토픽 자동 생성)
   ↓
[학생 발화]
   ↓
[1] 튜터 에이전트: 다음 유도 질문 1개 (6단계 프레임 따라)
    └ 병렬로 채점 에이전트: 직전 발화를 5축 채점 → 점수 누적 → 등급 갱신
   ↓
[반복] 최대 턴수 도달 시 → 요약 에이전트 마무리 발화 → 세션 잠금
```

- **5축 루브릭**: 개념이해 · 예시활용 · 논리전개 · 자기인식 · 능동탐구.
- **점수 누적·등급 산출**: 턴마다 점수를 더해 총점 비율로 티어(등급) 계산. 최대 턴수(예: 5~20)에 도달하면 마무리.
- **부정행위/이탈 방지**: 회피·주제 이탈 답변은 채점 에이전트가 낮은 점수(감점)를 매겨 자연스럽게 억제한다. (RAG 임계값 거절이 아니라 **채점 기반 유도**가 소크룸의 방식.)

➜ 이 흐름이 트랙 B에서 짓다로 재현할 **소크룸형 대화 튜터**의 골격이다. "이론은 이름만 알면 충분" 원칙에 따라, 임베딩·벡터DB 같은 기술보다 **주제 설정 → 유도 질문 프롬프트 → 발화 채점 → 등급 표시** 흐름을 프롬프트 패턴으로 구현하는 데 집중한다.

## 3. 글로벌 사례 — Khan Academy의 Khanmigo

소크룸과 가장 잘 맞는 비교 대상은 RAG 챗봇이 아니라 **소크라테스식 튜터**다.

- **소크라테스식 튜터**: 질문에 직접 답하지 않고 "되묻는다" — 소크룸의 핵심 원칙과 동일.
- **커리큘럼 바운드**: Khan Academy 콘텐츠·학습 목표 범위 안에서 대화 — 소크룸의 "주제 기반 대화"와 대응.
- **GPT 기반 + 가드레일**: K-12 안전 환경. "정답을 대신 풀어주지 않는다"는 교육 원칙을 시스템 프롬프트로 강제.
- **1년 만에 6.8만 → 70만 사용자**, 380개 학군 도입(2023→2024).

➜ 소크룸은 사실상 **"한국형 Khanmigo(소크라테스식 대화 튜터)"**. 연수에서 두 도구를 나란히 시연하면 "정답을 주지 않고 질문으로 유도하는 AI"의 가치가 명확해진다.

## 4. 안전성 / 교육 원칙 (트랙 B의 핵심)

소크룸의 안전성은 "자료 밖 거절"이 아니라 **교육적 대화 원칙을 프롬프트로 강제**하는 데서 나온다.

### 4.1 시스템 프롬프트 기반 대화 원칙 (가장 단순·효과적)

```
당신은 [학년]의 [주제] 학습을 돕는 소크라테스식 튜터입니다.
규칙:
1. 학생이 답을 물어봐도 절대 직접 답하지 마세요.
   대신 한 번에 하나씩 유도 질문을 던져 학생이 스스로 생각하게 하세요.
2. 질문은 명료화→가정→증거→관점→함의→메타인지 순서로 사고를 넓히세요.
3. 대화는 설정된 [주제] 범위 안에서 유지하고, 벗어나면 부드럽게 주제로 돌리세요.
4. 욕설/혐오/주제 무관 질문은 정중히 거절하고 학습으로 유도하세요.
```

### 4.2 안전·품질 계층

| 계층 | 역할 | 구현 난이도 |
|------|------|-------------|
| L1 입력 필터 | 욕설/위험 발화 사전 차단 | 낮음 (키워드+LLM 분류) |
| L2 시스템 프롬프트 | 소크라테스식 페르소나·"정답 직답 금지"·주제 유지 강제 | 낮음 |
| L3 발화 채점 유도 | 회피·이탈 답변에 낮은 점수 → 자연스러운 억제 | 중간 (채점 에이전트) |
| L4 교사 대시보드 | 등급·대화 실시간 확인·개입 | 운영 |

➜ 본 연수에서는 **L1·L2·L4**를 중심으로 하되, **L3(발화 채점을 통한 유도)**가 소크룸형 튜터의 차별점이다.

## 5. 트랙 B 학습자 산출물 후보 (본선 시작점)

연수 종료 시 교원이 짓다로 만들 수 있어야 할 도구의 MVP:

- **교사 화면**: **주제(텍스트/PDF/URL) + 난이도 + 최대 턴수** 입력 → 대화 튜터 링크 발급
- **학생 화면**: 닉네임 입력 → AI 튜터와 다회차 소크라테스식 대화
- **대화 엔진**: Solar API + 시스템 프롬프트로 "한 번에 하나씩 유도 질문" 생성
- **발화 채점**: 학생 발화를 5축(개념이해·예시활용·논리전개·자기인식·능동탐구)으로 채점 → 점수 누적
- **등급 표시**: 누적 점수로 티어(등급) 산출·표시, 최대 턴수 도달 시 마무리
- **교사 대시보드**: 학생별 등급·점수 + 개별 대화 로그 열람

> **검증 필요**: 짓다에서 (a) 다회차 대화 상태 유지, (b) 매 발화 채점을 위한 추가 LLM 호출, (c) 누적 점수·등급 계산을 어디까지 구현할 수 있는지. 5축 채점을 별도 프롬프트 호출로 붙일지, 튜터 응답과 한 번에 처리할지 표준화 필요. → **업스테이지·팀모노리스 협의 항목**

## 7. 위험요소 및 대응

- **위험 1**: 짓다에서 다회차 대화 + 발화별 채점 + 등급 누적 구현이 어려움
  - 대응 A: **소크룸형 스타터 프롬프트/템플릿**을 제공하고 교사는 주제·난이도·채점 기준만 바꾸기
  - 대응 B: 채점을 매 턴 별도 호출로 붙이기 어려우면, 마무리 시점 일괄 평가로 단순화
- **위험 2**: 주제 자료(PDF·URL) 저작권
  - 대응: 연수에서는 공개 학습자료(개정 교육과정 공개자료, 위키)로 시연
- **위험 3**: 학생이 프롬프트 우회로 "그냥 답 알려줘"를 관철
  - 대응: day1_07·day2_02에서 실제 우회 시도 → 시스템 프롬프트 보강으로 방어 체험
- **위험 4**: LLM이 유도 질문 대신 정답을 줘버림("정답을 주지 않는 AI" 원칙 붕괴)
  - 대응: 시스템 프롬프트 강화 + 교사 대시보드 대화 점검
