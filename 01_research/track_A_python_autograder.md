# 트랙 A 리서치 — Python 자동채점 + 오류 도우미

> 목적: 연수 트랙 A의 도메인(현존 도구·기술 패턴)을 파악해 학습 목표와 차시 설계의 근거로 삼는다.
> 작성일: 2026-06-01

## 1. 기준 도구 — 코들(Codle)의 파이썬 수업도구

코들은 학급 단위 파이썬 수업을 위한 SW교육 솔루션이고, 본 연수의 **벤치마크 + 출발점**.

### 1.1 코들이 제공하는 핵심 기능

- **파이썬 코딩 환경**: 브라우저에서 즉시 실행 가능한 Python 런너
- **자동 채점 문제**: 학생이 코드를 제출하면 즉시 채점·피드백
  - 가이드에서 "AI 테스트케이스 생성" 기능 명시 → **LLM이 채점용 테스트케이스를 만들어주는 패턴**
- **AI 튜터**: "학습자가 스스로 문제를 해결할 수 있도록" 돕는 도우미 (정답 X, 힌트 O)
- **AI 자동채점**: 서술형 항목 채점 전용 (코드 외 영역)
- **AI 퀴즈 생성**: PDF로 퀴즈 자동 생성
- **활동지 / 보드 / 공부방** 등 7가지 이상 활동 유형
- **교실 단위 운영**: 구성원 관리, 학습 분석 대시보드(진행도·실시간 분석)
- **교실 설정**에서 "파이썬 AI 도우미" / "활동지 AI 도우미" 사용 여부를 별도로 켜고 끌 수 있음 (가드레일 측면에서 중요)

### 1.2 코들에서 배울 수 있는 "수업도구 구조" 4요소

| 요소 | 코들의 구현 |
|------|-------------|
| 학생-교사 구분 | 교실(class) 단위, 교사가 학생 가입/구성원 관리 |
| 활동 배부 | 활동지·문제·코스 단위로 학생에게 배포 |
| 학생 결과물 제출 | 코드 제출 → 자동 채점 → 즉시 피드백 |
| 교사 대시보드 | 학습 분석 페이지, 진행도, 실시간 분석 |

➜ 연수 3차시 "수업도구 구조" 이론은 코들 화면을 그대로 4분면으로 분해해서 보여주면 효과적.

## 2. 외부 유사 사례 — 자동채점 + AI 오류 도우미

### 2.1 패턴 분류

| 패턴 | 사례 | 채점 방식 | AI 활용 |
|------|------|-----------|---------|
| Unit test 기반 | CodeGrade, PyTest autograding | 단위 테스트로 정답·오답 판정 | AI는 코드 품질·구조 보조 |
| Input/Output 매칭 | CodeGrade IO checking, 코드런 | 표준 입출력 비교 | 보조 |
| LLM 기반 채점 | PyEvalAI(2025), GPT-4-Turbo + RandomForest 하이브리드 | LLM이 코드 의미 평가 | 핵심 |
| 코드 품질 | Flake8, semgrep | 정적 분석 | 옵션 |
| AI 코드 도우미 | Replit Ghostwriter, CodeGrade AI Assistant | — | 오류 설명·힌트 제공, 정답은 안 주는 모드 존재 |

### 2.2 교육용 AI 도우미의 핵심 설계 원칙 (CodeGrade 사례)

- **개념을 설명하되 정답 코드는 제공하지 않음**
- **고치는 방향을 넛지(nudge)하지만 직접 수정해주지는 않음**
- **교사가 AI가 할 수 있는 말의 범위를 제어**
- **모든 대화 내역을 교사가 볼 수 있음**

이 4원칙은 코들 AI 튜터 / 소크룸과 정확히 일치 → **트랙 공통 가드레일 원칙**으로 채택 가능.

### 2.3 LLM 기반 코드 채점 연구 동향 (2024-2025)

- **PyEvalAI** (arXiv 2502.18425, 2025): Jupyter Notebook 채점 + 로컬 LLM으로 프라이버시 보존
- **MDPI 2025 연구**: GPT-4-Turbo + Random Forest 결합 → 인간 채점자와 유사한 정확도
- **CS1 코드 채점 평가** (arXiv 2511.14798): Direct vs Reverse 방법 비교, Gemini 1.5 Pro / GPT-4o 평가
- **공통 한계**: 복잡한 로직과 미묘한 오류에서 LLM이 인간 채점자보다 약함 → **테스트케이스 + LLM 설명 하이브리드**가 현실적

### 2.4 연수에서 시연 가능한 최소 패턴

가장 단순하면서 교육 효과 큰 조합:

```
[학생 코드 제출]
   ↓
[1] 테스트케이스 실행 (input/output 비교) → 통과/실패
   ↓
[2] 실패 시 → Solar LLM에게 "이 코드와 이 에러를 한국어로 학생에게 설명해줘.
              단, 정답 코드는 주지 마라. 어디를 다시 보라고 힌트만 줘." 호출
   ↓
[3] 학생에게 힌트 표시 + 교사 대시보드에 대화 기록
```

➜ 트랙 A의 **MVP 산출물** 후보로 이 구조를 그대로 채택할 수 있다.

## 3. 트랙 A 학습자 산출물 후보 (바이브톤 시작점)

연수 종료 시 교원이 짓다로 만들 수 있어야 할 도구의 MVP:

- **문제 1개를 등록**할 수 있는 교사 화면 (제목·설명·기대 입출력·테스트케이스 1-3개)
- **학생이 코드를 작성/제출**할 수 있는 화면 (브라우저 내 Python 실행)
- **자동 채점**: 테스트케이스 통과 여부
- **AI 오류 도우미**: 실패 시 Solar API 호출, 정답 차단 가드레일 프롬프트
- **교사 대시보드**: 학생별 제출 현황·AI 대화 기록 열람

> 짓다 환경에서 어디까지 가능한지 Phase 1 후속 단계에서 검증 필요 (브라우저 Python 실행은 짓다가 직접 지원하지 않을 수 있음 → Solar API + 가상 채점 / Pyodide 등 대안 확인).

## 4. 차시 설계 시사점

| 차시 | 트랙 A 관점 |
|------|--------------|
| 2차시 (수업도구 체험) | 코들 자동채점·AI 튜터 직접 사용 후 좋은 점·아쉬운 점 정리 |
| 3차시 (수업도구 구조) | 코들 화면을 4분면(학생-교사 구분·배부·제출·대시보드)으로 분해 |
| 4차시 (일단 만들기) | 짓다로 "문제 1개 + 코드 제출 + 통과 여부 표시" 최소 버전 |
| 7차시 (LLM 위험요소) | "정답 차단" 가드레일 프롬프트 작성 — 트랙 A의 핵심 안전장치 |
| 8차시 (Solar API 챗봇) | Solar API로 "코드 + 에러"를 받아 힌트만 반환하는 함수 작성 |
| 9-10차시 (트랙별 기술) | 테스트케이스 자동 실행 + 결과 LLM 설명 결합 패턴 |
| 11-13차시 (바이브코딩) | MVP 따라 만들기 → 자기 문제로 커스터마이즈 |

## 5. 위험요소 및 대응

- **위험 1**: 짓다가 브라우저 Python 실행을 지원하지 않을 가능성
  - 대응: Solar API에 "이 코드를 가상으로 실행하면 어떻게 될까" 시뮬레이션 / 또는 단순 문자열 매칭 / Pyodide 임베드
- **위험 2**: LLM이 정답 코드를 줘버림
  - 대응: 7차시에서 시스템 프롬프트 패턴 학습 + 8·9차시 실습에서 반복 검증
- **위험 3**: 50명이 동시에 Solar API를 호출 → 공용 키 레이트 리밋
  - 대응: 차시 흐름에서 호출 시점을 분산, 강사가 시연 → 학생 실습 분할
- **위험 4**: 자동 채점 결과가 부정확 → 학생 좌절
  - 대응: 연수에서는 "교사 검수 + 자동 채점" 하이브리드 강조
