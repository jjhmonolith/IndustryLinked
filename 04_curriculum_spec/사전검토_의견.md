## 2. 통화 핵심 — 연수 방향

### 전종현 대표의 고민

- 솔라(Solar) 모델·RAG·OCR·문서인식 같은 기술을 많이 보여줘야 할지, 선생님이 바이브 코딩으로 직접 도구를 만들게 하는 게 맞는지 모호.
- 기존 컨소시엄 커리큘럼은 AI 개발 원리·RAG·문서 AI 원리를 15시간 내내 다루는 구성이었으나 의미 없다고 판단해 전면 개편.

### 개편한 커리큘럼 방향

- 두 트랙: ① 코들 파이썬 자동채점·AI 튜터 ② 소크룸(챗봇형 기능).
- 각 기능의 AI 모델은 솔라 API로 구현(바이브 코딩 자체는 솔라로 안 함. 모델만 솔라).
- 콘셉트: "나도 에듀테크 도구를 만들 수 있다". 이론은 살짝, 직접 만들기 중심.
- 컨소시엄 강점 결합: 업스테이지(한국어 잘하는 모델) + 팀모노리스(에듀테크 제작 경험).

## 3. 연구사 핵심 조언

1. **기술 원리 설명에 몰입 X**. 정보교사라도 RAG·LLM 작동 원리를 깊이 알 필요 없음. 시연·설명은 *전체의 1/3~1/2 이내*. 직접 만들기에 무게.
2. **차별화 포인트**: "기존 교육용 언어·IDE가 못 하던 일을 솔라 기능이 더해져 해낸다."
3. **검증 안 된 기능 라이브 노출 금지**. 역효과 위험.
4. **심의 통과가 1차 관문**. 심의위원(교육학 박사·교수·운영진)은 콘텐츠 깊이가 아닌 *전반적 흐름과 연수 구현 가능성*을 본다. RAG 같은 용어는 아예 모를 수 있음 — "다 모르는 분" 전제.
5. **양식 작성**: 목표·의미 칸에 컨소시엄 의미를 담는다. 세부 강의 방법·내용 표는 *심플하게*. 복잡해지면 질문이 쏟아져 막힘. 디테일은 *교재에서* 풀면 됨.
6. **심의 발표 짧음** — 팀당 약 30분, 이번엔 팀이 많아 더 짧음. 임팩트 있게 던지고, 아닌 건 빨리 빼고, 큰 흐름만 정리.
7. **지금 디테일에 집착 X**. 어차피 교재 만들면서 다 바뀜. 논쟁보다 큰 그림 확정이 우선.

## 4. 합의된 결론

- 기술 시연보다 *선생님이 직접 만드는 경험*과 *문제 정의·기획 역량*에 초점.
- 잘 풀면 대규모 POC가 될 수 있음.
- 전 대표가 목요일에 자료를 다시 보내기로 함.
