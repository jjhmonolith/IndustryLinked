AI 수업도구, 이렇게 생겼습니다

완성본을 먼저 보고, 내 수업 문제로 첫 스케치를 그린다

사례 시연 · 트랙 A / 트랙 B 도구 제작 5단계 강사 이예진 / 팀모노리스
오프닝: 앞 시간에 '우리는 AI를 만드는 사람이 된다'를 들었지만 '만든다'가 감이 안 올 수 있음. 이틀 뒤 손에 쥘 완성품이 실제로 어떻게 생겼는지 먼저 보여주는 시간. 결론: 대단한 기술이 아니라 '내 수업의 반복 작업을 대신하는 작은 도구'.

보고, 이해하고, 스케치한다

  • 완성 도구 두 가지를 시연으로 눈에 담는다
  • 도구를 만드는 제작 5단계를 이해한다
  • 내 학교 수업 문제로 첫 스케치를 그린다 (입력→도움→결과)

오늘 손댈 건 5단계 중 딱 1단계, 문제 정의 하나입니다.

강조: "대단한 기술 아니라 작은 도구"로 진입장벽 낮추기. 오늘 과제는 문제 정의 하나뿐. 나머지는 이틀에 걸쳐 함께.

이틀 뒤, 이걸 만듭니다

지금부터 두 도구를 실제로 시연합니다 — 잘 관찰만 하세요

시연은 "완성본은 이렇게 생겼다"를 보여주는 목적. 라이브 시연 실패 대비 녹화·스크린샷 백업 대기(최형관). 오류 시 즉시 전환.

서로 다른 두 도구

트랙 A

자동채점 + AI 튜터

학생 코드를 자동으로 채점하고, 정답 대신 힌트·해설을 주는 도구

트랙 B

자료 기반 챗봇

교사가 넣은 수업자료 범위 안에서만 답하는 챗봇

샘플

지금 보시는 두 도구는 코들에 이미 있는 기능입니다. 이걸 샘플 삼아 내일 짓다에서 직접 만듭니다.

둘 다 예시일 뿐. 핵심은 '내 수업 문제'입니다.

지금 트랙을 고를 필요 없음 — 내일 선택. 두 도구는 코들 기능(샘플)이고, 내일 짓다에서 본인 버전을 제작. 본인 교과에 맞는 형태를 함께 찾아줌.

정답을 대신 써 주지 않는다

1

코드 제출

학생이 낸 파이썬 코드를 입력

2

자동 채점

테스트케이스로 통과·실패 판정

3

힌트·해설

정답 대신 "여길 다시 보세요"

정답을 주는 순간 학생은 생각을 멈춥니다.

화면: 코들 데모 — 코들의 파이썬 자동채점 기능. 학생 코드 넣으면 자동 채점 → 틀린 부분은 정답 대신 '이 부분 반복문 범위를 다시 보세요' 같은 힌트만. 오류 시 녹화 전환.

모르면 정직하게 "없어요"

  • 자료 안 질문 → 내 자료에서 답을 찾아 준다
  • 자료 밖 질문 → "제 수업자료엔 그 내용이 없어요"
정직한 AI

엉뚱한 답을 지어내지 않고 내가 준 범위 안에서만 답하게 만드는 것 — 이걸 내일 직접 만듭니다.

화면: 코들 데모. '광합성 명반응이 뭐야?'는 자료에서 답, 자료 밖 질문엔 정직하게 거절. 교실에서 지어내기가 왜 위험한지 각인.

'정직한 AI' 하나로 통합니다

트랙 A

정답 코드를 통째로 주지 않고 힌트만 준다

트랙 B

자료에 없으면 지어내지 않고 거절한다

왜 중요한가

교실에서 AI가 아는 척 지어내면 위험합니다. 범위를 지키는 정직함이 곧 신뢰입니다.

이 원칙이 오늘 시연의 핵심 메시지. 두 도구가 겉모습은 달라도 같은 철학. 내일 만들 때 이 규칙을 못박게 됨.

제작은 다섯 걸음

복잡해 보이지만, 오늘 여러분이 할 일은 1단계 하나뿐

"어떻게 만드느냐, 딱 다섯 단계." 2~5단계는 이틀에 걸쳐 함께 진행하니 지금 부담 갖지 말 것.

①만 오늘, 나머지는 이틀에 걸쳐

1

문제 정의

풀고 싶은 수업 문제 하나 — 오늘 여기까지

2

학습자 분석

누가·어떤 수준으로 쓰나

3

기능 정의

무엇을 해 주는 도구인가

4

자료·AI 결합

내 자료와 AI를 붙인다

5

점검·반복

써 보고 고친다

좋은 문제 하나만 고르면 절반은 끝입니다.

①문제 정의 → ②학습자 분석 → ③기능 정의 → ④자료·AI 결합 → ⑤점검·반복. 5단계 설명은 짧게, 실습 15분 반드시 확보.

내 수업 문제, 스케치하기

1차시에 적은 한 줄에 살을 붙일 시간

1차시에서 적은 '수업 문제 1줄'을 구체적 스케치로 발전시킴. 코들 보드에 두 칸 사전 생성됨.

코들 보드에 두 가지를 적습니다

1) 수업 문제

내 학교에서 풀고 싶은 수업 문제를 1~2문장으로.

2) 첫 스케치

무엇을 입력하면 → AI가 어떤 도움을 주고 → 어떤 결과가 나오면 좋을지.

# 스케치 예시
입력: 학생이 낸 2학년 함수 단원 오답
도움: 정답 대신 "어디를 다시 볼지" 힌트
결과: 학생이 스스로 고쳐 다시 제출
순회하며 스케치 3칸(입력→도움→결과)이 빈 교사에게 빈칸 채우기로 최소 산출물 확보. 최형관 함께 순회.

좁힐수록 좋은 도구가 나옵니다

한 단원

좋은 예

"2학년 함수 단원에서 학생이 오답을 내면 힌트를 주는 도구" — 이 정도면 완벽합니다.

문제가 광범위·추상적이면 "한 학기·한 단원·한 반"으로 좁히도록 예시 제공. 거창하게 가지 말 것.

이 스케치가 내일의 설계도

기록

코들 보드에 수업 문제 1~2문장 + 첫 스케치(입력→도움→결과)가 올라갔는지 확인하세요.

코드는 아직 한 줄도 안 썼지만, 가장 어려운 '무엇을 만들 것인가'를 방금 정하셨습니다.

코들 보드아직 제작 아님시연·스케치 단계
업로드 점검 필수. 아직 본격 제작은 아니고 문제 정의·스케치까지. 다음 차시로 자연스럽게 연결.
