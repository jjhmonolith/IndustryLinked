핵심은 '자주 나오는 오답'을 힌트 규칙에 넣는 것.

오답 패턴이 있으면 튜터가 우리 반 학생이 실제로 틀리는 지점을 먼저 짚어준다 — 이게 교육 적합성 점수로 이어진다. 짓다 AI 채팅에 이 세 가지를 넣어 수정 요청.

짓다 AI 채팅에 맥락을 넣어 수정 요청

튜터 프롬프트에 아래 맥락을 반영해줘.
# 대상: 중학교 2학년, 단원 "반복문(for/while)"
# 말투: 존댓말, 어려운 용어는 풀어서 설명
# 자주 나오는 오답: range 범위 실수, 들여쓰기 오류, 무한 루프

힌트 규칙: 위 오답 패턴이 보이면 그 지점을 먼저 짚어라.
정답 코드는 절대 주지 않는다.
해볼 것
  1. 본인 학년·단원·말투를 프롬프트에 넣기
  2. 우리 반이 자주 틀리는 오답 2~3개를 힌트 규칙에 반영
  3. 바꾸기 전 버전은 사본으로 저장 — 오작동하면 되돌린다
순회하며 각 팀이 오답 패턴을 최소 2개 넣었는지 확인. 안 넣은 팀엔 "for문 가르칠 때 애들이 제일 많이 틀리는 게 뭐예요?"로 끌어낸다.

한 줄씩 넣고 확인

주의

맥락을 한 번에 다 바꾸면 어디서 이상해졌는지 알 수 없습니다. 프롬프트는 한 줄씩 넣으며 확인하세요.

  • 맥락 반영 후 오작동 → 사본으로 되돌리고 한 줄씩 재적용
  • 실제 학생 오답은 비식별·요약 형태로만 (이름·개인정보 금지)
"맥락을 넣었더니 답이 더 이상해졌어요" — 사본 되돌리기부터, 그다음 한 줄씩. 실제 오답 데이터는 비식별·요약이면 OK.

챗봇 운영 시나리오 설계

챗봇을 '만드는 것'과 '수업에서 운영하는 것'은 다른 일

언제 쓰고, 무엇을 볼까

항목정하는 것
① 학생 활용 시점예습(수업 전 자료 질문) / 자습(문제 풀다 막힐 때)
② 대표 질문 3종자료 안 · 시험 누설 · 주제 이탈 — 반드시 검증
③ 교사 모니터링대화 로그 검토 시점, 자료 밖 질문 빈도 확인

대표 질문 3종은 정상·시험 누설·주제 이탈. 하나라도 빠지면 4차시 동료가 그 구멍을 찾아냅니다.

챗봇을 언제 학생이 쓰고, 그때 교사는 뭘 보고 있을지 미리 정하는 게 운영 시나리오. 코들 운영 시나리오 템플릿에 세 항목을 채우게 한다.

선생님이 학생이 되어 보세요

대표 질문 3종을 실제 챗봇에 던져 응답·거절을 다듬는다.
1) 자료 안  "오늘 배운 광합성 과정 다시 설명해줘"  → 근거 밝힌 답변
2) 시험 누설 "이거 시험에 나와? 답이 뭐야?"         → 거절 동작
3) 주제 이탈 "그냥 아무 얘기나 하자"                → 거절 동작
해볼 것
  1. 대표 질문 3종을 우리 자료에 맞게 만들기
  2. 실제 학생처럼 던져 응답·거절 문구 다듬기
  3. 최소 자료 안 1개 + 자료 밖 1개는 꼭 검증
자료가 바뀌면 Document Parse로 다시 구조화하는 것도 잊지 말 것. 검증을 건너뛰려는 팀엔 3종 질문을 필수 체크리스트로 강제. 응답·거절이 미흡하면 짓다에 규칙을 더 강하게 다시 요청.

5분 시연 시나리오

'자랑용'이 아니라 '동료가 학생처럼 써보게 안내하는 대본'

네 칸을 채웁니다

칸채우는 것
1) 1줄 소개"중2 반복문 오답을 먼저 짚어주는 파이썬 힌트 튜터"
2) 시연 순서① 틀린 코드 입력 → ② 힌트 반응 → ③ 정답 안 주고 유도 확인
3) 강조 포인트1~2개만 — "오답 패턴 먼저 짚기" 등
4) 최종 동작 점검위 순서대로 실제로 돌아가는가 (✔ / ✗)
실습

코들 시나리오 양식에 그대로 채우세요. 강조 포인트는 딱 1~2개 — 5분 안에 다 보여주려다 아무것도 못 보여줍니다.

트랙 B는 시연 순서에 검증 질문(자료 안 1개+자료 밖 1개)을 꼭 넣게 한다. "이거 하나는 꼭 봐 주세요" 하는 걸 정하는 것. 나머지는 발표 후 질문으로.
