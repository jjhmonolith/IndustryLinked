# [2일차 · 1차시 / 09:00–11:00 (2h)] 도구 만들기

**주강사**: 트랙 A(파이썬) 배영빈·박기영 / 트랙 B(소크룸) 이예진 / **[보조 강사]** 배치 / **분반**: 서울 트랙 A 2반·트랙 B 1반 / 부산 각 1반, 반당 40명(서울)·25명(부산)

## 학습 목표 (트랙 공통)
1. 1일차에 스케치한 아이디어를 트랙 주제에 맞는 '진짜 수업 도구'로 발전시킨다.
2. 트랙 A는 학생 파이썬 코드를 자동 채점하고 정답 대신 힌트를 주는 AI 튜터를, 트랙 B는 정한 주제로 학생과 대화하며 스스로 생각하게 이끌고 대화를 평가하는 튜터(소크룸형)를 만든다.
3. 코드를 직접 쓰지 않고, 짓다(팀모노리스 바이브코딩 플랫폼) AI 채팅에 말로 요청해 도구를 만들고 Solar를 연동해 본다.

> **오늘의 제작 도구는 '짓다'**: 왼쪽 AI 채팅에 한국어로 "이런 도구 만들어줘"라고 말하면 AI가 코드를 만들고, 오른쪽 라이브 미리보기에서 바로 확인한다. 바꾸고 싶으면 다시 말한다. 완성작은 갤러리에 공개·호스팅된다. 설치·로그인·명령어 없이 브라우저만.

### 짓다 AI 채팅 요청 예시 / 규칙
코드를 직접 쓰지 않고, 아래처럼 '무엇을·어떤 규칙으로' 만들지를 짓다 AI 채팅에 말로 요청한다. 채점은 정확히 맞음/틀림을 가르고, 힌트는 Solar가 만들되 **정답을 그대로 알려주지 않는다**는 규칙을 요청에 못 박는다.

```text
학생이 낸 파이썬 코드를 자동으로 채점하는 웹앱을 만들어줘.
- 내가 등록한 정답·예시와 비교해서 맞음/틀림을 정확히 가려 줘
- 잘못되거나 너무 오래 걸리는 코드가 들어와도 앱이 멈추지 않게 해줘

틀리면 정답을 그대로 알려주지 말고 힌트만 줘. 규칙:
- 정답이나 정답 코드는 절대 보여주지 마
- "어디가 왜 막혔는지"를 한 문장으로만 짚어줘
- 학생이 '해결 방법'을 누르면 그때 조금 더 자세히 안내해줘
- 힌트 문구는 Solar로 만들어줘
```

### 산출물
- 학생 코드를 자동 채점하고, 틀리면 정답 대신 힌트를 주는(원하면 해결 방법을 더 보여주는) 트랙 A 튜터 v1.

| 10:30–11:00 (20분) | 테스트 — 학생 역할로 대화해 보며 답을 바로 주지 않고 질문을 던지는지, 평가·등급이 도는지 미리보기로 확인 |

### 짓다 AI 채팅 요청 예시 / 규칙
내가 정한 대화 주제(직접 쓰거나 PDF·링크로 넣어 AI가 정리)를 바탕으로, 아래처럼 짓다 AI 채팅에 말로 요청한다. **답을 바로 알려주지 말고 질문을 던져 스스로 생각하게 한다**는 규칙을 요청에 못 박는다.

```text
'광합성'을 주제로 학생과 대화하는 학습 튜터 웹앱을 만들어줘. 모델은 Solar.
규칙:
- 답을 바로 알려주지 말고, 한 번에 하나씩 질문을 던져 스스로 생각하게 해줘
  (예: "왜 그렇게 생각해요?", "근거는 뭘까요?", "다른 관점도 있을까요?")
- 학생 답변을 다섯 가지 관점으로 평가해줘:
  개념 이해 · 예시 활용 · 논리 전개 · 자기 인식 · 능동적 탐구
- 점수가 쌓이면 등급이 오르게 해줘 (입문 단계에서 시작해 점점 높은 단계로)
- 학생은 닉네임만으로 쓰고, 교사는 학생별 등급·점수와 대화 내용을 볼 수 있게 해줘
```

### 산출물
- 정한 주제로 학생과 대화하며 답 대신 유도 질문을 던지고, 대화를 다섯 관점으로 평가해 등급을 매기는 트랙 B 대화 튜터 v1.

## 강사 강조 (공통)
- 오늘의 목표는 '기능을 많이'가 아니라 '내 수업에서 실제로 쓸 하나의 도구'를 동작시키는 것.
- 오늘은 코드를 직접 쓰지 않는다. 짓다 AI 채팅에 '무엇을·어떤 규칙으로' 만들지를 말로 요청하고, 미리보기로 확인·수정한다. "코딩 못 해도 됩니다".
- 트랙 A: 힌트는 정답을 그대로 알려주지 않는다. 학생 스스로 고치게 하는 것이 튜터의 핵심 — 이 규칙을 요청에 못 박는다.
- 트랙 B: 답을 바로 주지 않고 질문을 던져 스스로 생각하게 하는 것이 핵심. 대화를 평가해 등급이 오르게 하는 것까지 요청에 담는다.
- 막히면 옆 사람과 화면을 공유하고 보조 강사를 부를 것.
