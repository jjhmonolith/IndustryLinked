### 핵심 패턴 / 프롬프트 예시
자동 채점은 코드 실행 결과를 정답과 비교하고, 통과 여부에 따라 힌트·해설 프롬프트를 분기한다.

```python
def grade_submission(student_code: str, testcases: list[tuple]) -> dict:
    """정답 비교 기반 자동 채점. 통과/실패와 실패 케이스를 반환."""
    passed, failed = [], []
    for inp, expected in testcases:
        got = run_student_code(student_code, inp)   # 샌드박스 실행
        (passed if got == expected else failed).append((inp, expected, got))
    return {"score": len(passed) / len(testcases), "failed": failed}

# 실패 시 → 학생 수준 힌트 생성 (Solar LLM API)
HINT_PROMPT = """너는 중학생에게 파이썬을 가르치는 친절한 튜터다.
아래 학생 코드는 입력 {inp}에서 {expected} 대신 {got}을 출력했다.
[규칙] 정답 코드를 그대로 주지 마라. 학생이 스스로 고치도록
'어느 줄의 무엇이 왜 문제인지'를 한 문장으로 짚고, 다음 시도를 위한 질문 하나를 던져라.
학생 코드:
{student_code}"""
```

### 산출물
- 정답 비교 기반 자동 채점 + 수준별 힌트 + 코드 해설 튜터가 한 흐름으로 동작하는 트랙 A 도구 v1.

### 핵심 패턴 / 프롬프트 예시
Document Parse(구조화) → Information Extract(핵심 추출) → 지식 베이스 → 자료 범위 내 응답 파이프라인을 시스템 프롬프트로 강제한다.

```text
[시스템 프롬프트 — 자료 기반 응답 · 거절]
너는 아래 <학습자료>에만 근거해 답하는 학습 보조 챗봇이다.

규칙:
1) 답변은 반드시 <학습자료> 안의 내용으로만 구성한다.
2) 근거가 자료에 없으면 지어내지 말고 이렇게 거절한다:
   "그 내용은 이번 수업자료 범위에 없어요. 자료에 있는 OO, OO에 대해서는 도와줄 수 있어요."
3) 답변 끝에 근거가 된 자료의 항목(제목/소단원)을 표시한다.

<학습자료>
{information_extract_결과_핵심항목들}
</학습자료>

학생 질문: {question}
```

### 산출물
- 내 수업자료로 만든 지식 베이스 + 자료 범위 안에서만 답하고 밖은 거절하는 트랙 B 챗봇 v1.

## 강사 강조 (공통)
- 오늘의 목표는 '기능을 많이'가 아니라 '내 수업에서 실제로 쓸 하나의 도구'를 동작시키는 것.

- 트랙 B: 챗봇의 신뢰는 '모른다고 말하는 정직함'에서 나온다. 자료 밖 답변을 지어내면 도구 전체가 무너진다.
- 막히면 옆 사람과 화면을 공유하고 보조 강사를 부를 것.
