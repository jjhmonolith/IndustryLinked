# [2일차 · 1차시 / 09:00–11:00 (2h)] 도구 만들기

**주강사**: 트랙 A 배영빈(팀모노리스 책임) [류호선·신화준] / 트랙 B 김비치·김세윤(팀모노리스) [신희찬·이동연·이창환·민은실] / **분반**: 트랙별

## 학습 목표 (트랙 공통)
1. 1일차에 만든 챗봇 MVP·아이디어를 트랙 주제에 맞는 '진짜 수업 도구'로 발전시킨다.
2. 트랙 A는 학생 코드를 자동 채점·힌트·해설하는 AI 튜터를, 트랙 B는 내 수업자료 범위 안에서만 답하는 학습 챗봇을 구현한다.
3. 코드를 직접 쓰지 않고, 짓다(팀모노리스 바이브코딩 플랫폼) AI 채팅에 말로 요청해 도구를 만들고 Solar를 연동해 본다.

> **오늘의 제작 도구는 '짓다'**: 왼쪽 AI 채팅에 한국어로 "이런 도구 만들어줘"라고 말하면 AI가 코드를 만들고, 오른쪽 라이브 미리보기에서 바로 확인한다. 바꾸고 싶으면 다시 말한다. 완성작은 갤러리에 공개·호스팅된다. 설치·로그인·명령어 없이 브라우저만.

### 짓다 AI 채팅 요청 예시 / 규칙
코드를 직접 쓰지 않고, 아래처럼 '무엇을·어떤 규칙으로' 만들지를 짓다 AI 채팅에 요청한다. 채점은 정확히, 힌트·해설은 Solar가 생성하되 **정답 코드는 절대 노출하지 않는다**는 규칙을 요청에 못 박는다.

```text
파이썬 문제 하나를 풀게 하고, 학생이 제출한 코드를
미리 정한 테스트케이스로 자동 채점하는 웹앱을 만들어줘.
- 통과/실패를 정확히 갈라 보여주고, 틀린 케이스는 (입력, 기대값, 실제출력)을 표로
- 잘못되거나 오래 걸리는 코드도 앱이 멈추지 않게 안전하게 처리해줘

틀리면 정답 대신 힌트를 줘. 규칙:
- 정답 코드는 절대 보여주지 마
- "어느 줄의 무엇이 왜 문제인지"를 한 문장으로만 짚어줘
- 다음 시도를 위한 질문 하나를 던져줘
- 해설도 정답 코드 없이 틀린 부분과 이유를 학생 눈높이로 설명해줘
- 힌트·해설 문구는 Solar로 생성해줘
```

### 산출물
- 정답 비교 기반 자동 채점 + 수준별 힌트 + 코드 해설 튜터가 한 흐름으로 동작하는 트랙 A 도구 v1.

| 10:40–11:00 (20분) | 테스트 — 자료 안 질문에 근거 표시, 자료 밖·경계 질문에 지어내지 않고 거절되는지 미리보기로 확인 |

### 짓다 AI 채팅 요청 예시 / 규칙
day1에서 구조화·추출한 자료(핵심 항목)를 챗봇의 지식 베이스로 삼고, 아래처럼 짓다 AI 채팅에 요청한다. **자료 안에서만 답하고, 자료 밖은 지어내지 말고 정직하게 거절한다**는 규칙을 요청에 못 박는다.

```text
내가 넣어줄 수업자료(1개 단원) 범위 안에서만 답하는
학습 보조 챗봇 웹앱을 만들어줘. AI 모델은 Solar.
규칙:
- 답은 반드시 내가 준 자료 안 내용으로만 구성해
- 자료에 없는 건 지어내지 말고 이렇게 거절해:
  "그 내용은 이번 수업자료 범위에 없어요. 자료에 있는 OO, OO에 대해서는 도와줄 수 있어요."
- 답 끝에 근거가 된 자료 항목(제목/소단원)을 표시해줘
- 학생은 닉네임만으로 쓰고, 교사는 대화 로그를 볼 수 있게 해줘
```

### 산출물
- 내 수업자료로 만든 지식 베이스 + 자료 범위 안에서만 답하고 밖은 거절하는 트랙 B 챗봇 v1.

## 강사 강조 (공통)
- 오늘의 목표는 '기능을 많이'가 아니라 '내 수업에서 실제로 쓸 하나의 도구'를 동작시키는 것.
- 오늘은 코드를 직접 쓰지 않는다. 짓다 AI 채팅에 '무엇을·어떤 규칙으로' 만들지를 말로 요청하고, 미리보기로 확인·수정한다. "코딩 못 해도 됩니다".
- 트랙 A: 힌트는 정답 코드를 주지 않는다. 학생 스스로 고치게 하는 것이 튜터의 핵심 — 이 규칙을 요청에 못 박는다.
- 트랙 B: 챗봇의 신뢰는 '모른다고 말하는 정직함'에서 나온다. 자료 밖 답변을 지어내면 도구 전체가 무너진다 — 거절 규칙을 요청에 못 박는다.
- 막히면 옆 사람과 화면을 공유하고 보조 강사를 부를 것.

## 주요 위험·대응
| 위험 | 대응 |
|------|------|
| 학생 코드 실행 중 무한 루프·오류로 채점이 멈춤 | 요청에 "잘못되거나 오래 걸리는 코드도 앱이 멈추지 않게 처리해줘"를 넣어 재요청 |
| 라이브 미리보기가 안 뜨거나 깨짐 | 새로고침 → 요청을 더 구체적으로 쪼개 다시 요청 |
| 짓다 AI가 요청을 오해함 | 한 번에 하나씩(기능→규칙→데이터) 요청, 바꿀 부분만 집어 다시 말하기 |
| Solar 응답 실패로 힌트/답변이 안 나옴 | 연동·키 재확인, 실패 시 사용자용 안내 메시지로 폴백하도록 요청 |
| 구조화 자료가 표·수식으로 지저분함 | 텍스트가 깔끔한 단원부터 시작, 핵심 항목을 손으로 정리 후 진행 |
| 자료가 너무 커 지식 베이스가 산만함 | 오늘은 1개 단원으로 범위를 좁혀 지식 베이스 구성 |
