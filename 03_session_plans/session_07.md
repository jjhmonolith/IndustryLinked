# [7차시 / 50분] 각자 제작 — Solar API 챗봇

**주관**: 팀모노리스 + 업스테이지 멘토 / **분반**: 공통

## 학습 목표

1. 짓다에서 Solar API 최초 호출을 실행한다.
2. 6차시 가드레일을 시스템 메시지로 적용한다.
3. 본인 도구의 구조도(LLM 호출 위치 포함)를 작성한다.

## 진행 흐름

| 시간 | 내용 |
|------|------|
| 0-5분 | 도입 — 첫 API 호출, 양 옵션 안내 |
| 5-15분 | 공용 API 키 안내 + 짓다 호출 패턴 시연 |
| 15-40분 | 제작 — 옵션 A·B 중 1건 선택 |
| 40-48분 | 도구 구조도 작성, 코들 보드 이미지 카드 게시 |
| 48-50분 | 성취 기준 확인·다음 차시 안내 |

## 공용 API 키 (필수 준수)

- Day 1: 임시 공용 키 1건. 트랙별 분리는 9차시부터.
- 개인 노출 금지 — 짓다 환경 변수에만 저장.
- 키 분배: 강사 화면 표시 또는 인쇄물 배포.
- 요청 한도: 100명 동시 호출 시 한도 초과 가능. "1분 1회" 약속. 호출 시점을 5분 간격 분산.

## 옵션 A — 코드·오류 → 힌트 함수 (트랙 A 향)

- 입력: 학생 코드 + 오류 메시지
- 시스템 프롬프트: 6차시 "정답 차단" 가드레일
- 출력: 학생용 한국어 힌트 1~2문장
- 검증:
  - 의도적 오류 코드 1건 → 힌트 적절성 확인
  - "정답 코드 요청" 삽입 → 정답 비제공 확인
- 확장: 동일 코드 2회 입력 시 "유사 질문" 응답

## 옵션 B — 발췌·질문 → 응답/거절 함수 (트랙 B 향)

- 입력: 교과서 발췌 + 학생 질문
- 시스템 프롬프트: 6차시 "범위 제한" 가드레일 + "발췌 근거 응답"
- 출력: 한국어 응답 1~3문장 또는 "교재에서 확인 어려움"
- 검증:
  - 발췌 내 질문 → 응답
  - 발췌 외 질문 → 거절
  - 비속어·주제 무관 → 거절
- 확장: "교재 참고 부분" 표시 추가

## 강사 강조

- 본 차시 목표는 *작동 확인*이다. UX는 11~13차시.
- 오류는 학습 기회다. 오류 메시지를 짓다에 그대로 입력해 해결한다.
- 공용 키 노출 시 즉시 차단. 환경 변수만 사용.

## 사전 준비물

- 공용 API 키(Day 1 임시 1건)
- 짓다 기본 템플릿 2종(옵션 A·B)
- 멘토 5~7명(100명 / 멘토 1인당 15~20명). 옵션별 분담
- API 장애 대응 영상

## 성취 기준

- 모든 교원이 짓다 화면에 응답 1회 이상 출력(최소 합격선).
- 가드레일 준수 1회 이상 확인.
- 모든 교원이 도구 구조도를 코들 보드에 게시.

## 주요 위험·대응

| 위험 | 대응 |
|------|------|
| API 키 노출 | 5분 도입에 "코드 직접 기입 금지" 안내. 멘토 적발·시정 |
| API 호출 실패 | 기본 템플릿 사용. 멘토 1:1 디버그 |
| 조기 완료자 | 미선택 옵션도 시도(트랙 결정 자신감) |
| 진도 지연자 | 멘토가 시연 코드 복제, 작동시킨 후 단계별 이해 |

## 짓다·코들

- 짓다: 15~48분
- 코들 보드: 40~48분 — 도구 구조도 이미지 카드. 동료 구조도가 실시간 노출
