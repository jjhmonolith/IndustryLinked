# [본선 · 3차시 / 14:00–17:00 (3h)] 피드백 분석과 도구 개선 계획 수립 멘토링 — 의견을 어떻게 반영할까

**담당**: 팀모노리스 멘토(배영빈·류호선·이동연·이창환·이예진) + 업스테이지 멘토(이준엽·전영훈·최선웅·김남혁·조은비) / **분반**: 5분반(40명/반)

## 학습 목표
1. 받은 동료 피드백 중 자기 도구에 실제 적용 가능한 의견을 선별한다.
2. 우선순위·작업 단위·예상 효과를 갖춘 도구 개선 계획을 수립한다.
3. 전문가 1:n 멘토링을 받으며 개발 환경에서 도구를 직접 개선하고 전·후 차이를 기록한다.

| 14:10–14:50 (40분) | 적용 가능 의견 추리기 — 2차시 피드백 중 자기 도구에 반영 가능한 항목 선별, 반영 어려운 의견은 사유 메모 | 전담 멘토 |

| 16:50–17:00 (10분) | 개선 결과 정리 및 발표 준비 안내 — 최종 발표에서 강조할 개선점 1~2개 선정 | 전담 멘토 |

## 강사 강조
- 모든 피드백을 반영하려 하지 말고, 효과가 크고 오늘 안에 실현 가능한 개선부터 우선하도록 강조한다.
- 개선은 반드시 개발 환경에서 실제 동작으로 확인하고, 전·후 차이를 스스로 기록하게 한다.
- 멘토는 대신 만들어 주지 않고 참가자가 직접 손을 움직이도록 안내(질문·힌트 중심).

## 사전 준비물
- 2차시에서 취합한 4항목별 동료 피드백 모음.
- 도구 개선 계획 양식(우선순위·작업 단위·예상 효과 열).
- 개발 환경(Colab/API 키), Solar LLM API 키.

## 성취 기준(산출물)
- 적용/보류로 분류된 피드백 선별 목록(보류 사유 포함).
- 우선순위·작업 단위·예상 효과가 담긴 개선 계획표.
- 개선 전·후 동작 차이 기록과 실제 개선 반영된 도구 버전.

## 주요 위험·대응
| 위험 | 대응 |
|------|------|
| 욕심내어 개선 범위를 과도하게 잡음 | 우선순위 상위 1~2개로 범위 제한, 멘토가 실현 가능한 단위로 쪼개도록 조정 |
| 개발 난도로 개선이 막힘 | 1:n 멘토링에서 막힌 지점 우선 지원, 대안 접근(설정·프롬프트 조정 등) 제시 |
| AI 응답 품질 개선이 눈에 안 보임 | 개선 전·후 동일 입력으로 비교 기록해 변화 가시화 |
| 소크룸형 대화 튜터가 답을 흘리거나 주제를 벗어남 | 유도 질문이 정답을 흘리지 않는지, 대화 평가(다섯 관점)가 적절한지, 주제를 잘 다루는지 점검·조정 |
| 파이썬 튜터의 채점·힌트 문제 | 채점 정확도와 힌트가 정답을 흘리지 않는지 점검·조정 |
| 멘토 1인당 인원 과다로 대기 발생 | 반별 2개 기관 멘토 분담, 대기 팀은 개선 계획 문서화 병행 |

## 도구 사용
- 짓다(개발 환경, Colab/API 키): 도구 개선 실습.
- Solar LLM API: AI 응답 품질 개선·검증 — 트랙 B는 유도 질문·대화 평가(다섯 관점) 조정, 트랙 A는 채점·힌트 조정.
- 코들: 개선 계획·기록 제출.
