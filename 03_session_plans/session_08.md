# [8차시 / 50분] Solar API로 간단한 챗봇 만들어보기

**주관**: 업스테이지 주도 + 팀모노리스 멘토링 / **분반**: 트랙별 분반 (과제 다름)

## 학습 목표

1. 짓다에서 Solar API를 호출하는 첫 코드를 동작시킨다.
2. 7차시에서 만든 가드레일 프롬프트를 챗봇 시스템 메시지로 적용한다.
3. 자기 트랙 MVP에서 LLM 호출이 어떤 위치에 들어가는지 다이어그램으로 그린다.

## 진행 흐름

| 시간 | 내용 |
|------|------|
| 0-5분 | 도입 — "오늘 첫 API 호출. 어제 만든 가드레일이 진짜 동작하는지 본다." |
| 5-15분 | **공용 API 키 안내** + 짓다에서 호출 패턴 시연 (강사 화면) |
| 15-35분 | **본 실습**: 트랙별 챗봇 만들기 (각자 노트북) |
| 35-42분 | "이 챗봇이 내 MVP의 어느 자리에 들어가나" 다이어그램 스케치 |
| 42-50분 | 팀별 공유 + 트러블슈팅 |

## 공용 API 키 안내 (중요)

- 트랙(교실)별 공용 키 1개 사용 → **개인 노출 금지** (짓다 환경 변수에 저장)
- 키 분배 동선: 강사가 화면에 띄우거나, 종이로 배포
- 레이트 리밋: 50명이 동시에 호출하면 막힐 수 있음 → "1분에 한 번씩만" 같은 약속

## 트랙 A — "코드 + 에러 → 힌트만 주는 함수" 만들기

- **요구사항**:
  - 함수 입력: 학생 코드(문자열) + 에러 메시지(문자열)
  - 시스템 프롬프트: 7차시에서 작성한 "정답 차단" 가드레일
  - 출력: 학생에게 보여줄 한국어 힌트 1-2문장
- **검증**:
  - 일부러 틀린 코드 1개를 넣어 힌트가 적절한지 확인
  - "정답 코드 줘"라고 사용자 입력에 끼워넣어도 안 주는지 확인
- **확장(시간 남으면)**: 같은 코드를 두 번째로 물어보면 "이미 비슷한 질문을 했어요" 응답

## 트랙 B — "교과서 발췌문 + 학생 질문 → 답변 (or 거절)" 만들기

- **요구사항**:
  - 함수 입력: 교사 미리 넣은 교과서 한 단락(문자열) + 학생 질문(문자열)
  - 시스템 프롬프트: 7차시에서 작성한 "범위 제한" 가드레일 + "주어진 발췌문을 근거로만 답"
  - 출력: 한국어 답변 1-3문장 (or "교재에서 확인 어려움")
- **검증**:
  - 발췌문 안 내용 질문 1개 → 답
  - 발췌문 밖 내용 질문 1개 → 거절
  - 욕설/주제 무관 1개 → 거절
- **확장(시간 남으면)**: 답변에 "교재 ~~ 부분 참고" 표시 추가

## 강사 핵심 메시지

- "오늘은 *동작하는 것*이 목표. 예쁘게 만드는 건 11-13차시."
- "에러가 나면 환영. 에러 메시지를 짓다에게 그대로 붙여넣고 물어보자 (바이브코딩 핵심 동작)"
- "공용 키 절대 노출 금지. 환경 변수로만."

## 사전 준비물 (강사·운영)

- 공용 API 키 (트랙별 1개)
- 짓다 스타터 템플릿 (5분 안에 호출까지 가능한 최소 코드)
- 멘토 4-5명 (50명 / 멘토 1인당 10-12명 순회)
- API 장애 백업: 호출 시연 영상

## 체크포인트

- **모든 학습자가 짓다 화면에 응답이 한 번 이상 출력됨** (이것이 8차시의 최소 합격선)
- 자기 챗봇이 7차시 가드레일을 지키는지 확인 1회 이상 수행

## 흔한 실패 패턴과 대응

| 실패 | 대응 |
|------|------|
| API 키 노출 사고 | 시작 5분에 "절대 코드에 직접 쓰지 말 것" 경고. 멘토가 순회하며 즉시 적발 |
| 호출이 안 됨 | 짓다 스타터 템플릿 사용. 멘토가 1:1 디버그 |
| 너무 빨리 끝낸 학습자 | 확장 과제 제시 (위 "확장" 참고) |
| 너무 늦은 학습자 | 멘토가 강사 시연 코드를 그대로 복사해 일단 동작시킨 뒤 차근차근 이해 |
