# [8차시 / 50분] Solar API로 간단한 챗봇 만들기 + 트랙 확정

**주관**: 업스테이지 주도 + 팀모노리스 멘토링 / **분반**: 공통(단일 트랙). **차시 끝에 트랙 확정.**

## 학습 목표

1. 짓다에서 Solar API를 호출하는 첫 코드를 동작시킨다.
2. 7차시에서 만든 가드레일 프롬프트를 챗봇 시스템 메시지로 적용한다.
3. **자기가 9차시부터 들어갈 트랙(A/B)을 확정한다.**

## 진행 흐름

| 시간 | 내용 |
|------|------|
| 0-5분 | 도입 — "오늘 첫 API 호출. 두 가지 챗봇 옵션 중 본인 끌리는 쪽을 골라 시도. 끝에 트랙 결정." |
| 5-15분 | **공용 API 키 안내** + 짓다에서 호출 패턴 시연 (강사 화면, 두 옵션 모두 시연) |
| 15-35분 | **본 실습**: 옵션 A·B 중 1개 골라 챗봇 만들기 |
| 35-42분 | "이 챗봇이 내 도구의 어느 자리에 들어가나" 다이어그램 스케치 → **코들 보드** 이미지 카드 |
| 42-48분 | 팀별 공유 + 트러블슈팅 |
| 48-50분 | **트랙 확정** — **코들 퀴즈** "9차시부터 들어갈 트랙은? (A/B)" |

## 공용 API 키 안내 (중요)

- **트랙별 공용 키 2개**를 8차시부터 사용 시작 — 다만 8차시는 단일 트랙 진행이므로 운영팀이 학습자 옵션 선택에 따라 키 라우팅 결정. 단순화: 8차시는 임시 공용 키 1개 사용 후 9차시부터 트랙별 분리.
- **개인 노출 금지** (짓다 환경 변수에 저장)
- 키 분배 동선: 강사가 화면에 띄우거나, 종이로 배포
- 레이트 리밋: 100명이 동시에 호출하면 막힐 수 있음 → "1분에 한 번씩만" 같은 약속 + 5분 간격으로 옵션 A·B 호출 시점 분산

## 옵션 A — "코드 + 에러 → 힌트만 주는 함수" (트랙 A 향)

- **요구사항**:
  - 함수 입력: 학생 코드(문자열) + 에러 메시지(문자열)
  - 시스템 프롬프트: 7차시 "정답 차단" 가드레일
  - 출력: 학생에게 보여줄 한국어 힌트 1-2문장
- **검증**:
  - 일부러 틀린 코드 1개를 넣어 힌트가 적절한지 확인
  - "정답 코드 줘"라고 사용자 입력에 끼워넣어도 안 주는지 확인
- **확장(시간 남으면)**: 같은 코드를 두 번째로 물어보면 "이미 비슷한 질문을 했어요" 응답

## 옵션 B — "교과서 발췌문 + 학생 질문 → 답변 (or 거절)" (트랙 B 향)

- **요구사항**:
  - 함수 입력: 교사 미리 넣은 교과서 한 단락(문자열) + 학생 질문(문자열)
  - 시스템 프롬프트: 7차시 "범위 제한" 가드레일 + "주어진 발췌문을 근거로만 답"
  - 출력: 한국어 답변 1-3문장 (or "교재에서 확인 어려움")
- **검증**:
  - 발췌문 안 내용 질문 1개 → 답
  - 발췌문 밖 내용 질문 1개 → 거절
  - 욕설/주제 무관 1개 → 거절
- **확장(시간 남으면)**: 답변에 "교재 ~~ 부분 참고" 표시 추가

## 트랙 확정 안내 (48-50분)

- **코들 퀴즈** 객관식: "9차시부터 들어갈 트랙은? A(자동채점+오류도우미) / B(소크룸+RAG)"
- 선택 기준 안내 (학습자에게):
  - 오늘 옵션 A·B 중 어느 쪽이 더 손에 맞았는가?
  - 7차시에서 어느 가드레일 패턴이 본인에게 더 끌렸나?
  - 2차시에서 코들/소크룸 중 어느 도구 자체에 더 끌렸나?
- 강사·운영팀이 즉시 분포 확인 → 다음날 트랙별 분반 운영 확정

## 강사 핵심 메시지

- "오늘은 *동작하는 것*이 목표. 예쁘게 만드는 건 11-13차시."
- "에러가 나면 환영. 에러 메시지를 짓다에게 그대로 붙여넣고 물어보자."
- "공용 키 절대 노출 금지. 환경 변수로만."
- "**트랙 결정은 오늘 옵션 경험이 가장 큰 신호**. 직관 따라가도 좋다. 1-7차시 학습은 두 트랙 모두에 동일하게 적용된다."

## 사전 준비물 (강사·운영)

- 공용 API 키 (8차시 임시 1개 + 다음날 트랙별 2개)
- 짓다 스타터 템플릿 2종 (옵션 A·B, 5분 안에 호출까지 가능한 최소 코드)
- 멘토 5-7명 (100명 / 멘토 1인당 15-20명 순회). 옵션 A·B에 따라 분담
- API 장애 백업: 호출 시연 영상
- **코들 퀴즈** 트랙 확정 객관식 사전 등록

## 체크포인트

- **모든 학습자가 짓다 화면에 응답이 한 번 이상 출력됨** (8차시 최소 합격선)
- 자기 챗봇이 7차시 가드레일을 지키는지 확인 1회 이상 수행
- **모든 학습자가 트랙 확정 퀴즈 응답 완료** (이게 다음날 분반의 필수 입력)

## 흔한 실패 패턴과 대응

| 실패 | 대응 |
|------|------|
| API 키 노출 사고 | 시작 5분에 "절대 코드에 직접 쓰지 말 것" 경고. 멘토가 순회하며 즉시 적발 |
| 호출이 안 됨 | 짓다 스타터 템플릿 사용. 멘토가 1:1 디버그 |
| 너무 빨리 끝낸 학습자 | 안 고른 옵션도 시도 (양쪽 다 경험 → 트랙 결정 더 자신감) |
| 너무 늦은 학습자 | 멘토가 강사 시연 코드를 그대로 복사해 일단 동작시킨 뒤 차근차근 이해 |
| 트랙 결정을 미루고 싶어함 | "오늘 안 정하면 다음날 분반이 안 됨. 직관 OK, 나중에 후회해도 14·15차시에서 트랙 교차 체험 가능" |
| 한쪽 트랙 응답 분포가 심하게 쏠림(예: 90:10) | 운영팀과 즉시 공유, 분반 공간·멘토 재배치 (이는 운영 영역) |

## 짓다 / 코들 사용 시점

- **짓다**: 15-42분 — 본격 사용 시작
- **코들 보드**: 35-42분 — 다이어그램(도구 구조 + LLM 호출 위치) 사진 카드
- **코들 퀴즈**: 48-50분 — 트랙 확정 객관식 (강사가 즉시 분포 확인)
