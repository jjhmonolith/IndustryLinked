# [본선 · 2차시 / 11:00–13:00 (2h)] 수업 시연과 동료 피드백 — 사용자 관점에서 도구 점검

**담당**: 최형관(팀모노리스 팀장) / **분반**: 5분반(40명/반)

## 학습 목표
1. 분반 내에서 자기 AI 수업 도구를 정해진 시간 안에 효과적으로 시연한다.
2. 시연 평가 4항목(사용 편의성·교육 적합성·AI 응답 품질·사용자 시점 명확성) 기준으로 동료 도구를 점검한다.
3. 단순 우열 비교가 아니라 개선 단서를 도출하는 건설적 피드백을 주고받는다.

## 진행 흐름
| 시간 | 내용 | 담당 |
|------|------|------|
| 11:00–11:15 (15분) | 시연·피드백 방식 안내 — 팀당 5분 시연 + 5분 질의응답, 평가 4항목 기준 설명, 피드백 시트 배부 | 최형관 |
| 11:15–12:45 (90분) | 분반 내 도구 시연 — 팀당 5분 시연 + 5분 질의응답(15~20팀/반), 멘토 동석·추가 코멘트 | 최형관·전담 멘토 |
| 12:45–12:57 (12분) | 사용자 관점 동료 피드백 정리 — 팀별로 받은 피드백을 4항목별로 취합·분류 | 최형관 |
| 12:57–13:00 (3분) | 오후 멘토링 연결 안내 — 취합한 피드백을 오후에 어떻게 반영할지 예고 | 최형관 |

## 강사 강조
- 시연은 기능 전체를 보여주기보다 "학생이 실제로 쓰는 핵심 흐름"을 5분 안에 보여주도록 안내한다.
- 피드백은 "좋다/나쁘다"가 아니라 4항목 중 어디를 어떻게 바꾸면 좋을지 구체적 단서로 남기게 한다.
- 시간 배분을 엄격히 지켜 15~20팀이 모두 시연 기회를 갖도록 진행한다.

## 사전 준비물
- 1차시 재정립 워크시트와 학습자 시점 스케치.
- 동료 피드백 시트(평가 4항목 구조, 반별 배포).
- 시연용 도구 접속 환경(코들·개발 환경·Solar LLM API), 짓다 갤러리 등록본.

## 성취 기준(산출물)
- 팀별 5분 시연 완료 기록(시연 순서·소요 시간).
- 4항목별로 정리된 동료 피드백 모음(팀당 최소 3건 이상).

## 주요 위험·대응
| 위험 | 대응 |
|------|------|
| 팀 수가 많아 시연 시간이 밀림 | 5분+5분 타이머 엄격 운영, 멘토가 반별로 진행 속도 관리 |
| 피드백이 인상평(막연한 칭찬/비판)에 그침 | 4항목 시트로 구조화, 항목별 "개선 단서 1개 이상" 규칙 적용 |
| 시연 중 도구·AI 응답 오류 발생 | 오류 상황 자체를 AI 응답 품질 점검 사례로 활용, 멘토가 즉시 대안 시연 지원 |
| 소수 팀에 피드백이 쏠림 | 멘토가 조를 순환시켜 전 팀이 균등하게 피드백 받도록 조정 |

## 도구 사용
- 짓다 갤러리: 도구 전시·동료 평가 시트 연동.
- 코들: 시연 순서·피드백 시트 배포·수합.
- 개발 환경·Solar LLM API: 실시간 시연 및 AI 응답 품질 확인.

## 다음 차시
점심(13:00–14:00) 이후 3차시(14:00–17:00)에서는 오늘 받은 피드백 중 적용 가능한 의견을 추려 개선 계획을 세우고, 전문가 멘토링을 받으며 개발 환경에서 도구를 고도화한다.
