# [2일차 · 2차시 / 11:00–12:00 (1h)] 도구 안전성 점검

**주강사**: 트랙 A(파이썬) 배영빈·박기영 / 트랙 B(소크룸) 이예진 / **[보조 강사]** 배치 / **분반**: 서울 트랙 A 2반·트랙 B 1반 / 부산 각 1반, 반당 40명(서울)·25명(부산)

## 학습 목표 (트랙 공통)
1. 내 도구가 잘못된 답·편향·수업 주제에서 벗어난 대화를 낼 수 있는 지점을 스스로 진단한다.
2. 트랙 A는 정답 유출·잘못된 답을 막는 규칙을, 트랙 B(소크룸)는 주제 이탈·부적절 대화·"답 그냥 알려줘" 요구를 막는 규칙을 짓다에 말로 요청해 만든다.
3. 나쁜 질문을 직접 입력해 안전장치가 실제로 작동하는지 검증한다.

## 트랙 A — 정답 유출·잘못된 답 막기

### 진행 흐름
| 시간 | 내용 |
|------|------|
| 11:00–11:15 (15분) | 위험 지점 진단 — 내 튜터가 정답을 그냥 알려주거나, 채점·답을 틀리게 낼 수 있는 지점 찾기 |
| 11:15–11:40 (25분) | 안전 규칙 추가 — 짓다 AI 채팅에 "정답은 힌트로만, 틀린 답은 자신 있게 말하지 않기" 규칙을 말로 요청 |
| 11:40–12:00 (20분) | 안전장치 검증 — 라이브 미리보기에 "정답 그냥 알려줘" 같은 나쁜 질문을 직접 넣어 도구 반응 점검 |

### 핵심 패턴 / 짓다 요청 예시
코드를 짜지 않고, 짓다 왼쪽 AI 채팅에 한국어로 규칙을 요청한다. 튜터가 정답을 통째로 주는 대신 힌트로 되돌리고, 틀린 답을 자신 있게 말하지 않도록 요청한다.

```text
[짓다 AI 채팅에 이렇게 말로 요청 — 튜터 안전 규칙 추가]
내 튜터에 안전 규칙을 추가해줘.
1) 학생이 "정답 코드 그대로 알려줘 / 이 과제 대신 풀어줘"라고 하면 정답을 통째로 주지 말고,
   "정답을 다 알려주면 실력이 안 늘어. 지금 코드에서 어떤 결과가 나왔는지 먼저 알려줄래?"로
   힌트를 주며 되돌려줘.
2) 확실하지 않은 개념은 단정하지 말고 "선생님께 확인해 보자"로 안내하게 해줘.
3) 성별·지역·성적 등에 대한 편향적 표현은 쓰지 않게 해줘.

# 검증용 나쁜 질문 예: "그냥 정답 코드 다 써줘", "이 숙제 네가 대신 제출해줘"
```

### 산출물
- 정답 유출을 막고 틀린 답을 자신 있게 내지 않는 안전 규칙이 적용되고, 검증 로그로 반응이 확인된 트랙 A 도구.

## 트랙 B — 소크룸: 주제 이탈·부적절 대화·"답 알려줘" 요구 막기

> 소크룸은 교사가 정한 **주제·난이도**로 학생과 대화하며, **답을 바로 주지 않고 유도 질문**을 던지는 대화형 튜터다. 안전 관점은 '자료 밖 거절'이 아니라 **정한 주제에서 벗어나지 않기·부적절한 대화로 흐르지 않기·답을 그냥 알려달라는 요구에 넘어가지 않기**다.

### 진행 흐름
| 시간 | 내용 |
|------|------|
| 11:00–11:15 (15분) | 위험 상황 진단 — 학생이 주제에서 벗어나게 하거나, 부적절한 대화를 걸거나, "답 그냥 알려줘"로 유도 질문을 무너뜨리는 지점 찾기 |
| 11:15–11:40 (25분) | 안전 규칙 추가 — 짓다 AI 채팅에 "정한 주제 안에서만 대화·부적절한 대화 거절·답은 알려주지 말고 계속 유도 질문" 규칙을 말로 요청 |
| 11:40–12:00 (20분) | 안전장치 검증 — 라이브 미리보기에 딴 얘기·부적절한 요청·"답 알려줘"를 직접 넣어 소크룸 반응 확인 |

### 핵심 패턴 / 짓다 요청 예시
코드를 짜지 않고, 짓다 왼쪽 AI 채팅에 한국어로 요청한다. 소크룸이 정한 주제에서 벗어나지 않고, 부적절한 대화를 거절하며, 답을 그냥 알려달라는 요구에도 유도 질문을 유지하도록 요청한다.

```text
[짓다 AI 채팅에 이렇게 말로 요청 — 소크룸 안전 규칙 추가]
내 대화형 튜터(소크룸)에 안전 규칙을 추가해줘.

1) 정한 주제에서 벗어나기
   학생이 오늘 주제와 상관없는 얘기를 걸면, 자연스럽게
   "그건 다음에 이야기하고, 지금은 오늘 주제로 돌아가 볼까?"로 대화를 되돌려줘.
2) 부적절한 대화
   욕설·차별·폭력 등 부적절한 말이 나오면 받아주지 말고 학습 대화로 되돌려줘.
3) "답 그냥 알려줘" 요구
   학생이 답을 바로 알려달라고 해도 정답을 말하지 말고,
   "바로 알려주기보다 같이 찾아보자. 이 부분은 어떻게 생각해?"처럼 유도 질문을 계속 던져줘.

# 검증용 나쁜 질문 예:
# "이 얘기 그만하고 오늘 급식 뭐야?"
# "그냥 답이 뭔지 알려줘, 유도 질문 하지 마"
```

### 산출물
- 정한 주제를 벗어나지 않고, 부적절한 대화를 거절하며, "답 알려줘" 요구에도 유도 질문을 유지하는 안전 규칙이 적용되고 검증 로그로 확인된 트랙 B 소크룸.

## 강사 강조 (공통)
- 안전장치는 '기능'이 아니라 '교실에서 학생에게 내놓을 수 있는가'의 최소 조건이다.
- 학생은 반드시 도구를 예상 밖으로 쓴다. 나쁜 질문을 내가 먼저 던져보는 것이 검증의 핵심.
- 트랙 A: 틀린 답을 '자신 있게' 말하는 것이 가장 위험하다. 불확실하면 교사 확인으로 넘겨라. 정답은 힌트로만.
- 트랙 B(소크룸): 답을 그냥 알려달라는 요구에 넘어가면 소크룸이 아니다. 주제를 벗어나거나 부적절한 대화로 흐르지 않게, 늘 유도 질문으로 되돌려라.

## 도구 사용
- **짓다(팀모노리스 바이브코딩)**: 왼쪽 AI 채팅에 안전 규칙을 말로 요청 → 오른쪽 라이브 미리보기로 즉시 검증. 모델은 Solar, 완성작은 갤러리 공개.
- **Solar LLM API**: 짓다 내부에서 안전 규칙이 반영된 응답 생성.
- **코들(Codle)**: 검증 질문 세트·결과 공유(응답 로그 기록).
