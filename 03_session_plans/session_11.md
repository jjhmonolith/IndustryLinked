# [11차시 / 50분] 바이브코딩 — 기획 + 따라 만들기 시작

**주관**: 팀모노리스 + 멘토 다수 / **분반**: 트랙별 분반, 3-5인 팀

## 학습 목표

1. 자기 수업 맥락에 맞는 도구의 **기획서(1쪽)**를 30분 안에 쓴다.
2. 팀모노리스 제공 트랙별 베이스라인을 짓다에 띄우고 동작을 확인한다.
3. 자기 기획과 베이스라인의 차이(=커스텀해야 할 것) 목록을 적는다.

## 진행 흐름

| 시간 | 내용 |
|------|------|
| 0-5분 | 도입 — 바이브코딩 3시간 흐름 안내 (11차시 기획+시작, 12차시 완성, 13차시 커스텀) |
| 5-35분 | **기획 30분** — 1쪽 기획서 작성 |
| 35-48분 | **베이스라인 띄우기** — 짓다에 트랙별 스타터 프로젝트 클론 및 동작 확인 |
| 48-50분 | "내 기획 vs 베이스라인 차이" 메모 — 12차시 입력 |

## 기획서 양식 (1쪽, 학습자 배포)

```
1. 제목: ______________________________
2. 누구의 어떤 문제를 풉니까? (한 문장)
   ______________________________

3. 학생은 무엇을 입력하고 무엇을 받습니까?
   입력: ______________________________
   결과: ______________________________

4. 교사는 무엇을 미리 준비하고 무엇을 봅니까?
   준비: ______________________________
   확인: ______________________________

5. 4요소 매핑:
   - 학생-교사 구분: ____________
   - 활동 배부: ____________
   - 결과물 제출: ____________
   - 교사 대시보드: ____________

6. LLM 호출 지점 (Solar API):
   - 호출 1: ____________ (입력→출력)
   - 호출 2(옵션): ____________

7. 가드레일:
   - 정답·이탈 차단 규칙 1줄: ____________

8. 이번 연수에서 만들 *최소 동작 버전(MVP)*은:
   ______________________________

9. *덜 중요해서 빼는 것*은:
   ______________________________
```

## 트랙 A — 베이스라인 스타터 제공

팀모노리스가 미리 만들어 짓다에 올려둘 **트랙 A 스타터**:

- 화면 1: 문제 보기 + 코드 입력란 + 제출 버튼
- 화면 2: 자동 채점 결과 (통과/실패)
- 화면 3: 실패 시 Solar 힌트 (정답 차단 가드레일 적용)
- 화면 4: (옵션) 교사 대시보드 — 학생별 시도 수·통과율·자주 막힌 지점

학습자 작업은: **스타터를 자기 기획에 맞게 변형**. (예: 수학 교사라면 문제를 수학 함수 작성으로, 과학이라면 데이터 분석 코드로)

## 트랙 B — 베이스라인 스타터 제공

팀모노리스가 미리 만들어 짓다에 올려둘 **트랙 B 스타터**:

- 화면 1: 닉네임 + 단원 선택 입장
- 화면 2: 학생 챗봇 화면 (RAG + 가드레일 적용)
- 화면 3: (옵션) 교사 대시보드 — 학생별 대화 로그·차단된 시도

학습자 작업은: **스타터에 자기 단원 자료를 넣고 가드레일·페르소나를 자기 학년에 맞게 조정**.

## 강사 핵심 메시지

- "기획 30분에 *깊이 고민하지 말고* 일단 1쪽 채우세요. 12-13차시에서 고치면 됩니다."
- "베이스라인 띄우기에 막히면 멘토에게 *바로* 부르세요. 11차시에 동작 안 하면 12차시가 어렵습니다."
- "내가 빼는 것이 명확해야 만들 수 있습니다. 기획서 9번이 가장 중요."

## 사전 준비물

- 짓다 트랙 A·B 스타터 프로젝트 (사전 검증 완료)
- 기획서 종이 양식 또는 구글독스 템플릿
- 멘토 5-7명 / 트랙 (50명 / 멘토 1인 ≈ 7-10명)
- 트랙별 "수업 시나리오 카드" 10장 — 기획이 막힌 교원에게 영감용 (예: 코딩 자가 검사 카드, 단원별 회독 챗봇 카드 등)

## 체크포인트

- 모든 팀원이 기획서 1쪽을 작성 완료
- 짓다에 베이스라인이 떠 있고 동작한다 (배포 링크 클릭 → 화면 표시)
- "차이 목록" 메모 작성 (12차시 입력)

## 흔한 실패 패턴과 대응

| 실패 | 대응 |
|------|------|
| 기획에서 막혀 시간 다 씀 | 멘토가 "수업 시나리오 카드" 1장 골라주고 "이걸로 일단 가자" |
| 욕심 부려 MVP가 너무 큼 | 9번 항목(빼는 것)을 더 채우게 함. 기능 줄이기를 가르치는 시간 |
| 베이스라인이 안 떠짐 | 멘토 즉시 1:1. 강사 시연 화면을 빔에 띄워두기 |
| 팀원 간 기획 의견 충돌 | "오늘은 각자 자기 MVP 1개씩이라도 OK". 합의 안 되면 분리 |

## 짓다 / 구글독스 사용 시점

- **짓다**: 35-50분 — 베이스라인 클론·실행
- **구글독스**: 5-35분 기획서, 48-50분 차이 메모

## 다음 차시 연결

→ 12차시는 50분 내내 따라 만들기. 11차시에서 베이스라인이 안 떠있는 팀은 12차시 시작이 어렵다 → 멘토가 점심시간에 따라잡기 지원 (운영).
